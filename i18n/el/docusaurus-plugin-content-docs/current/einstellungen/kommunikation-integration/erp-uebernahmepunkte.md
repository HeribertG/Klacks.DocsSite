# Σημεία ανάληψης ERP

Στις Ρυθμίσεις > Εισαγωγή (ορατό μόνο στη λειτουργία εμπειρογνώμονα), στην κάρτα «Σημεία απόθεσης ERP», διαμορφώνετε τον τρόπο με τον οποίο οι παραγγελίες από ένα εξωτερικό σύστημα ERP εισάγονται αυτόματα στο Klacks ως αρχεία XML.

## Πώς λειτουργεί

**Τρεις τρόποι παράδοσης:** Το σύστημα ERP μπορεί να τοποθετεί αρχεία XML σε έναν φάκελο στον διακομιστή του Klacks (το Klacks τα ανακτά αυτόματα σύμφωνα με το χρονοδιάγραμμα, μόλις ένα αρχείο παραμείνει αμετάβλητο για 10 δευτερόλεπτα), να τα προωθεί απευθείας μέσω HTTPS-POST σε ένα endpoint εισαγωγής (με ταυτοποίηση μέσω token πρόσβασης), ή μια διαχειρίστρια να ανεβάζει το αρχείο XML χειροκίνητα σε αυτή τη σελίδα με μεταφορά και απόθεση (drag-and-drop· η εισαγωγή ξεκινά αμέσως). Δεν υπάρχει SFTP· εισάγονται μόνο αρχεία XML στη μορφή `ErpOrderImport`.

**Το σημείο παραλαβής (Drop-Point)** είναι το κεντρικό γραμματοκιβώτιο, διαχειριζόμενο από το ίδιο το Klacks, για όλα τα αρχεία εισαγωγής — εμφανίζει τρεις περιοχές: Εισερχόμενα (παρελήφθησαν ή βρίσκονται αυτή τη στιγμή σε εισαγωγή), Επεξεργασμένα (με σύνοψη ανά αρχείο) και Σφάλματα (μη αναγνώσιμα ή μη έγκυρα αρχεία μαζί με την αιτία σφάλματος, με δυνατότητα επανεισαγωγής ή διαγραφής). Ένα χρονοδιάγραμμα (έκφραση cron, προεπιλογή ωριαία) καθώς και ένας διακόπτης ενεργοποίησης για παύση ελέγχουν την αυτόματη ανάκτηση.

**Ποιος τρόπος ταιριάζει σε ποια εγκατάσταση;** Σε έναν υπολογιστή γραφείου (εγκατάσταση Windows) ο προφανής τρόπος είναι ο φάκελος· ο προεπιλεγμένος φάκελος είναι `C:\ProgramData\Klacks\ErpImport\erp\orders`. Είναι προστατευμένος, μόνο το SYSTEM και οι διαχειριστές επιτρέπεται να γράφουν εκεί: ένας διαχειριστής πρέπει να δώσει στον λογαριασμό με τον οποίο εκτελείται η εξαγωγή του ERP το δικαίωμα «Τροποποίηση» ακριβώς στον φάκελο `erp\orders`, όχι σε ολόκληρο τον φάκελο `ProgramData\Klacks`. Σε έναν δικό σας διακομιστή Docker ο φάκελος είναι ένας απλός φάκελος του διακομιστή: το αρχείο Compose προσαρτά τον φάκελο `erp-import` δίπλα στο `docker-compose.yml` (μπορεί να αλλάξει μέσω `KLACKS_ERP_IMPORT_HOST_DIR`) στο `/app/ErpImport`, και μέσα στο container η διαδρομή του φακέλου είναι `/app/ErpImport/erp/orders`. Η εγκατάσταση αναφέρει τη διαδρομή του διακομιστή μέσω `KLACKS_ERP_IMPORT_HOST_PATH` (την ορίζει το πρόγραμμα εγκατάστασης)· ένα ERP στον υπολογιστή του διακομιστή γράφει απευθείας σε αυτόν τον φάκελο, και ο λογαριασμός με τον οποίο εκτελείται η εξαγωγή χρειάζεται δικαίωμα εγγραφής ακριβώς σε αυτόν τον φάκελο. Παλαιότερες εγκαταστάσεις είχαν έναν ονομασμένο τόμο (named volume)· το περιεχόμενό του αντιγράφεται μία φορά στον φάκελο (βλ. το README για On-Prem, ενότητα «Upgrading from a named volume»). Στην κάρτα εμφανίζεται η διαδρομή του φακέλου (σε Docker ο φάκελος του διακομιστή, από κάτω η διαδρομή μέσα στο container) με ένα κουμπί αντιγραφής. Σε μια εγκατάσταση που φιλοξενούμε εμείς δεν υπάρχει πρόσβαση σε φακέλους του διακομιστή: προώθηση (push) με token πρόσβασης ή χειροκίνητη μεταφόρτωση.

**Τα tokens πρόσβασης** χρειάζονται μόνο όταν ένα σύστημα ERP παραδίδει αρχεία μέσω push. Κάθε token ξεκινά με `klacks_erp_`, ισχύει για 1–730 ημέρες (προεπιλογή 365) και εμφανίζεται σε απλό κείμενο **μόνο μία φορά, κατά τη δημιουργία**. Ένα τέτοιο token ισχύει αποκλειστικά για το endpoint εισαγωγής, όχι για την υπόλοιπη πρόσβαση στο API, και μπορεί να ανακληθεί ανά πάσα στιγμή.

**Επεξεργασία:** Οι παραγγελίες αντιστοιχίζονται σε έναν υπάρχοντα ή νέο πελάτη βάσει του αναγνωριστικού συστήματος προέλευσης και της εξωτερικής αναφοράς πελάτη (ή, εναλλακτικά, εταιρείας/ταχυδρομικού κώδικα/οδού) και δημιουργούνται αρχικά ως πρόχειρο (draft), το οποίο οι υπεύθυνοι προγραμματισμού πρέπει να ελέγξουν και να σφραγίσουν. Μια τροποποιημένη νέα παράδοση μιας ήδη σφραγισμένης παραγγελίας ολοκληρώνει αυτόματα την παλιά και δημιουργεί μια νέα, συνδεδεμένη έκδοση· αμετάβλητες επαναληπτικές παραδόσεις δεν προκαλούν καμία ενέργεια.

## Καλό να το γνωρίζετε

- Εσφαλμένες μεμονωμένες παραγγελίες (π.χ. χωρίς ημέρα της εβδομάδας ή με διπλή αναφορά) απορρίπτονται, χωρίς να εμποδίζουν τις υπόλοιπες έγκυρες παραγγελίες του ίδιου αρχείου· το αρχείο εμφανίζεται παρ' όλα αυτά στην περιοχή Επεξεργασμένα, με ένδειξη προειδοποίησης, και οι απορριφθείσες παραγγελίες μπορούν να αναπτυχθούν μαζί με την αιτία τους.
- Τα αρχεία δεν μετακινούνται ούτε αρχειοθετούνται: παραμένουν στον φάκελο και η κατάστασή τους καταγράφεται στη βάση δεδομένων. Τα αρχεία που επεξεργάστηκαν με επιτυχία διαγράφονται αυτόματα μετά από 90 ημέρες· τα αρχεία στην περιοχή Σφάλματα παραμένουν μέχρι να εισαχθούν ξανά ή να διαγραφούν.
- Η ακριβής μορφή XML (υποχρεωτικά πεδία, μορφές ημερομηνίας, λογική ημέρας εβδομάδας) τεκμηριώνεται στο εγχειρίδιο απευθείας στη σελίδα ρυθμίσεων, καθώς και μέσω ενός αρχείου παραδείγματος που μπορεί να ληφθεί.
- Αυτή η διαμόρφωση βρίσκεται στην περιοχή Ρυθμίσεων και επομένως προορίζεται αποκλειστικά για διαχειριστικούς ρόλους.
