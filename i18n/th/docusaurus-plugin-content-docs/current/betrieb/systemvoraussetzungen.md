# ความต้องการของระบบและโครงสร้าง

Klacks ทำงานเป็น Docker stack บนเซิร์ฟเวอร์ของคุณเอง หน้านี้อธิบายว่าบริการใดจะเริ่มทำงานและวิธีกำหนดขนาดของโฮสต์ — รวมถึงค่าที่วัดได้ซึ่งเป็นพื้นฐานของคำแนะนำ

## โครงสร้าง: ห้าบริการ

แพ็กเกจ On-Premise เริ่มเฉพาะสิ่งที่จำเป็นต่อการใช้งานเท่านั้น:

| บริการ | อิมเมจ | หน้าที่ |
|---|---|---|
| `klacks-postgres` | `pgvector/pgvector:pg17` | ฐานข้อมูล ส่วนขยายเวกเตอร์รวมมาให้แล้ว |
| `klacks-api` | `ghcr.io/heribertg/klacks-api` | แบ็กเอนด์ ย้ายข้อมูลและเติมข้อมูลลงฐานข้อมูลตอนเริ่มต้น |
| `klacks-ui` | `ghcr.io/heribertg/klacks-ui` | หน้าจอใช้งาน Angular ให้บริการผ่าน nginx |
| `klacks-updater` | `ghcr.io/heribertg/klacks-updater` | ติดตั้งการอัปเดตที่มีลายเซ็น (api และ ui พร้อมกัน) |
| `klacks-proxy` | `nginx:alpine` | ยุติ TLS และทำหน้าที่ reverse proxy |

บริการภายในของผู้พัฒนา (คลังความรู้สำหรับการพัฒนา การตลาด มาร์เก็ตเพลส pgAdmin certbot หน้าจอ Blazor) **ไม่ได้**รวมมาโดยตั้งใจ คุณในฐานะผู้ดูแลระบบจึงเห็นเฉพาะสแต็กของคุณเอง

## สิ่งที่โฮสต์ต้องมี

- **RAM 8 GB และ 4 vCPU** เป็นขั้นต่ำ (ดูการคำนวณด้านล่าง)
- Docker Desktop (Windows/macOS) หรือ Docker Engine พร้อม Compose v2 (Linux) แบบ **amd64 หรือ arm64**
- พอร์ต **80 และ 443** ที่ว่างอยู่ — เขียนทับได้ผ่าน `HTTP_PORT` และ `HTTPS_PORT`
- การเข้าถึง HTTPS **ขาออก** ไปยัง `ghcr.io` (อิมเมจ) และ `github.com` (ไฟล์ manifest การอัปเดตที่มีลายเซ็น)
- ไม่บังคับ: การเข้าถึง `klacks-software.ch:7553` สำหรับแพ็กเกจประเทศและปลั๊กอินภาษาจากมาร์เก็ตเพลส

## หน่วยความจำ: ทำไมต้อง 8 GB และจะเกิดอะไรขึ้นกับโฮสต์ที่เล็กกว่า

Klacks เรียกใช้โมเดลค้นหาสองตัว (embedder และ reranker) **ภายในกระบวนการ** `klacks-api` เอง เซสชัน ONNX ทั้งสองอยู่ในหน่วยความจำอย่างถาวร — ไม่ถูกถอดออกหลังจากถามทุกครั้ง

วัดบนโฮสต์ production ของผู้พัฒนาเมื่อวันที่ 12.09.2026:

- ภาระพื้นฐานของกระบวนการ: ประมาณ 1'017 MB
- Embedder: ประมาณ 1'171 MB
- Reranker: ประมาณ 116 MB
- รวม: ระดับคงที่ประมาณ **2'304 MB**
- ภายใต้ขีดจำกัด 2'560 MB เคอร์เนลได้ยุติคอนเทนเนอร์ที่ 2'471 MB (OOM)

ด้วยเหตุนี้ Compose ที่มาพร้อมระบบจึงตั้งค่า **3'584M** และ 3,0 CPU ให้ `klacks-api` โดยปิดการถอดออกเมื่อว่าง คำนวณรวมทั้งสแต็ก: 3'584M (api) + 2'048M (postgres) + 3 × 256M (ui, updater, proxy) = **6'400 MiB** ส่วนที่เหลือของ 8 GB เก็บไว้สำหรับระบบปฏิบัติการและแคชไฟล์

**โฮสต์ที่เล็กกว่า ประมาณ 3 GB สำหรับ `klacks-api`:** ให้ตั้งค่า**ทั้งสอง**บรรทัดต่อไปนี้ใน `.env` — ห้ามตั้งเฉพาะบรรทัดหน่วยความจำอย่างเดียวเด็ดขาด:

```bash
KLACKS_API_MEMORY_LIMIT=2560M
KLACKS_API_IDLE_UNLOAD_MINUTES=30
```

การถอดออกเมื่อว่างจะปล่อยเซสชันหนึ่งหลังจาก 30 นาทีที่ไม่มีการเข้าถึง ราคาที่ต้องจ่าย: คำถามถัดไปหลังจากนั้นจะโหลดเซสชันใหม่ (ประมาณ 2,2–2,9 วินาทีสำหรับ embedder ประมาณ 1,1 วินาทีสำหรับ reranker) ค่าระหว่าง 1 ถึง 5 จะถูกปรับเป็น 5 ส่วน `0` หมายถึง: ไม่ถอดออกเลย

## CPU: แกนน้อยลงทำให้ช้าลงเท่านั้น ไม่ทำให้พัง

การค้นหาทำงานได้แม้มีแกนน้อยลง แต่จะช้าลง — reranker เป็นขั้นตอนที่ใช้การคำนวณหนักที่สุด วัดได้: 2'994–3'163 ms สำหรับผู้สมัคร 25 รายที่ 3,0 CPU เทียบกับ 4'339–4'860 ms ที่ 1,5 CPU ซึ่งบริการยังใช้เวลาอีก 7,15 วินาทีในสถานะถูกจำกัด (throttle) สำหรับโฮสต์ที่เล็กกว่า:

```bash
KLACKS_API_CPU_LIMIT=1.5
```

โควตา CPU ของสแต็กรวมกันได้ 4,75 บน 4 vCPU โดยตั้งใจ: โควตาคือเพดาน ไม่ใช่การจองไว้ และบริการต่าง ๆ ไม่เคยพุ่งสูงสุดพร้อมกัน

## ข้อมูลที่ควรทราบ

- **รหัสผ่านและกุญแจต้องคงที่** `POSTGRES_PASSWORD` ถูกฝังลงในวอลุ่มข้อมูลตั้งแต่การเริ่มต้นครั้งแรก — การเปลี่ยนภายหลังจะทำให้ฐานข้อมูลกลายเป็นข้อมูลกำพร้า `JWT_SECRET` ใช้ลงนามเซสชัน การเปลี่ยนจะทำให้ผู้ใช้ทุกคนถูกออกจากระบบ ตัวติดตั้งจะคงทั้งสองค่าไว้ทุกครั้งที่รันซ้ำ
- **`COMPOSE_PROJECT_NAME=klacks`** ถูกกำหนดตายตัวเพื่อให้โฮสต์และบริการอัปเดตชี้ไปยังโปรเจกต์ Compose เดียวกันโดยไม่ขึ้นกับชื่อโฟลเดอร์ อย่าเปลี่ยนอีกหลังการติดตั้ง
- **`KnowledgeIndex__WarmupEnabled=false` ไม่ใช่ตัวเลือกด้านหน่วยความจำ** มันเพียงเลื่อนการสร้างระบบค้นหาจากตอนเริ่มต้นไปเป็นคำขอแชตครั้งแรก ในการใช้งานต่อเนื่อง เซสชันก็ยังอยู่ในหน่วยความจำเหมือนเดิม มีประโยชน์เฉพาะเมื่อโฮสต์ล้มเหลวเรื่องหน่วยความจำตอนเริ่มต้น
- **มี API มากกว่าหนึ่งอินสแตนซ์?** ถ้าอย่างนั้นคุณต้องมี SignalR backplane Klacks ไม่ได้ให้มาด้วย: ให้จัดเตรียมบริการที่เข้ากันได้กับ RESP เอง (เช่น Valkey — ใช้สัญญาอนุญาต BSD-3 ตั้งแต่ 7.4 ต่างจาก Redis) และเปิดใช้ sticky upstream (`ip_hash`) ที่เตรียมไว้ในแม่แบบ nginx หากไม่มี backplane จะทำงานเพียงอินสแตนซ์ `klacks-api` เดียวเท่านั้น เหมือนการติดตั้งทุกรายในปัจจุบัน
- **โปรไฟล์ประเทศ:** ตัวติดตั้งรู้จัก 30 โปรไฟล์: `ae`, `at`, `ch`, `cn`, `cz`, `de`, `dk`, `es`, `fi`, `fr`, `gb`, `gr`, `id`, `il`, `it`, `jp`, `kr`, `li`, `my`, `nl`, `no`, `pl`, `pt`, `ro`, `sa`, `se`, `th`, `tw`, `us`, `vn` โปรไฟล์จะกำหนดค่าตอนเริ่มต้นครั้งแรก ได้แก่ ภาษา ประเทศ/ภูมิภาคและเขตเวลา ปฏิทินวันหยุด วันหยุดสุดสัปดาห์และวันเริ่มต้นสัปดาห์ ขีดจำกัดเวลาทำงาน สิทธิ์วันหยุดพักผ่อน ค่าตอบแทนเพิ่มเติม ระบบปลายทางการส่งออกเงินเดือนเริ่มต้น (สำหรับสวิตเซอร์แลนด์ เช่น `abaconnect-ch`) รวมถึงแม่แบบตามอุตสาหกรรม — สำหรับ Spitex เช่น แม่แบบกฎการวางแผน "CH Spitex Standard" หากไม่มีโปรไฟล์ Klacks จะเริ่มต้นแบบเป็นกลาง และคุณตั้งค่าทุกอย่างเอง
