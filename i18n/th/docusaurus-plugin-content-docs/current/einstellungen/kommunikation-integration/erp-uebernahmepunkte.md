# จุดรับข้อมูล ERP

ที่ การตั้งค่า > นำเข้า (แสดงเฉพาะในโหมดผู้เชี่ยวชาญ) การ์ด “จุดรับข้อมูล ERP” คุณกำหนดค่าวิธีการนำเข้าคำสั่งซื้อจากระบบ ERP ภายนอกในรูปแบบไฟล์ XML เข้าสู่ Klacks โดยอัตโนมัติ

## วิธีการทำงาน

**สามช่องทางในการส่งข้อมูล:** ระบบ ERP สามารถวางไฟล์ XML ไว้ในโฟลเดอร์บนเซิร์ฟเวอร์ Klacks (Klacks จะดึงไฟล์เหล่านั้นไปโดยอัตโนมัติตามตารางเวลา เมื่อไฟล์ไม่มีการเปลี่ยนแปลงเป็นเวลา 10 วินาที) หรือส่งไฟล์แบบ push ผ่าน HTTPS-POST ไปยัง endpoint สำหรับนำเข้าโดยตรง (ยืนยันตัวตนด้วยโทเคนการเข้าถึง) หรือผู้ดูแลระบบอัปโหลดไฟล์ XML ด้วยตนเองในหน้านี้ผ่านการลากและวาง (การนำเข้าจะเริ่มทันที) ไม่มี SFTP และจะนำเข้าเฉพาะไฟล์ XML ในรูปแบบ `ErpOrderImport` เท่านั้น

**จุดรับข้อมูล (Drop-Point)** เป็นเสมือนตู้จดหมายกลางที่ Klacks จัดการเองสำหรับไฟล์นำเข้าทั้งหมด โดยแสดงสามส่วน คือ ขาเข้า (ได้รับแล้วหรือกำลังนำเข้าอยู่) ประมวลผลแล้ว (พร้อมสรุปรายไฟล์) และข้อผิดพลาด (ไฟล์ที่อ่านไม่ได้หรือไม่ถูกต้องพร้อมเหตุผล และสามารถนำเข้าซ้ำหรือลบได้) ตารางเวลา (นิพจน์ Cron ค่าเริ่มต้นคือทุกชั่วโมง) และสวิตช์เปิด/ปิดใช้งานควบคุมการดึงข้อมูลอัตโนมัติ

**ช่องทางใดเหมาะกับการติดตั้งแบบใด?** บนพีซีสำนักงาน (การติดตั้ง Windows) ช่องทางที่เหมาะที่สุดคือโฟลเดอร์ โฟลเดอร์เริ่มต้นคือ `C:\ProgramData\Klacks\ErpImport\erp\orders` โฟลเดอร์นี้ได้รับการป้องกัน มีเพียง SYSTEM และผู้ดูแลระบบเท่านั้นที่เขียนได้ ผู้ดูแลระบบต้องให้สิทธิ์ “แก้ไข” (Modify) แก่บัญชีที่ใช้รันการส่งออกจาก ERP เฉพาะโฟลเดอร์ `erp\orders` เท่านั้น ไม่ใช่ทั้งโฟลเดอร์ `ProgramData\Klacks` บนเซิร์ฟเวอร์ Docker ของคุณเอง โฟลเดอร์นี้เป็นโฟลเดอร์ปกติของเซิร์ฟเวอร์ ไฟล์ Compose จะเมานต์โฟลเดอร์ `erp-import` ที่อยู่ข้างไฟล์ `docker-compose.yml` (เปลี่ยนได้ผ่าน `KLACKS_ERP_IMPORT_HOST_DIR`) เข้ากับ `/app/ErpImport` และภายในคอนเทนเนอร์โฟลเดอร์นี้มีพาธเป็น `/app/ErpImport/erp/orders` การติดตั้งจะรายงานพาธบนเซิร์ฟเวอร์ผ่าน `KLACKS_ERP_IMPORT_HOST_PATH` (ตัวติดตั้งเป็นผู้ตั้งค่า) ERP บนเครื่องเซิร์ฟเวอร์จะเขียนลงในโฟลเดอร์นี้โดยตรง และบัญชีที่ใช้รันการส่งออกต้องมีสิทธิ์เขียนเฉพาะโฟลเดอร์นี้เท่านั้น การติดตั้งรุ่นเก่ามีวอลุ่มที่มีชื่อ (named volume) เนื้อหาในวอลุ่มจะถูกคัดลอกไปยังโฟลเดอร์เพียงครั้งเดียว (ดู README ของ On-Prem หัวข้อ “Upgrading from a named volume”) บนการ์ดจะแสดงพาธของโฟลเดอร์ (บน Docker คือโฟลเดอร์ของเซิร์ฟเวอร์ และด้านล่างคือพาธภายในคอนเทนเนอร์) พร้อมปุ่มสำหรับคัดลอก สำหรับการติดตั้งที่เราเป็นผู้โฮสต์ จะไม่มีสิทธิ์เข้าถึงโฟลเดอร์บนเซิร์ฟเวอร์ ให้ใช้การ push ด้วยโทเคนการเข้าถึงหรือการอัปโหลดด้วยตนเอง

**โทเคนการเข้าถึง** จำเป็นเฉพาะเมื่อระบบ ERP ส่งไฟล์แบบ push เท่านั้น โทเคนแต่ละตัวเริ่มต้นด้วย `klacks_erp_` มีอายุการใช้งาน 1–730 วัน (ค่าเริ่มต้น 365 วัน) และจะแสดงเป็นข้อความธรรมดา **เพียงครั้งเดียวตอนสร้าง** เท่านั้น โทเคนนี้ใช้ได้เฉพาะกับ endpoint สำหรับนำเข้าเท่านั้น ไม่ใช่สำหรับการเข้าถึง API ส่วนอื่น และสามารถเพิกถอนได้ตลอดเวลา

**การประมวลผล:** คำสั่งซื้อจะถูกจับคู่กับลูกค้าที่มีอยู่แล้วหรือลูกค้าที่สร้างใหม่ โดยอ้างอิงจากรหัสระบบต้นทางและหมายเลขอ้างอิงลูกค้าภายนอก (หรือใช้ชื่อบริษัท/รหัสไปรษณีย์/ถนนแทนหากไม่มี) และจะถูกสร้างขึ้นเป็นฉบับร่างก่อน ซึ่งผู้วางแผนต้องตรวจสอบและปิดผนึก การส่งซ้ำที่มีการเปลี่ยนแปลงของคำสั่งซื้อที่ปิดผนึกไปแล้ว จะปิดคำสั่งซื้อเดิมโดยอัตโนมัติและสร้างเวอร์ชันใหม่ที่เชื่อมโยงกัน ส่วนการส่งซ้ำที่ไม่มีการเปลี่ยนแปลงจะไม่ก่อให้เกิดผลใด ๆ

## ข้อมูลที่ควรทราบ

- คำสั่งซื้อรายการที่มีข้อผิดพลาด (เช่น ไม่มีวันในสัปดาห์ หรือมีหมายเลขอ้างอิงซ้ำ) จะถูกปฏิเสธ โดยไม่ปิดกั้นคำสั่งซื้อที่ถูกต้องรายการอื่นในไฟล์เดียวกัน แต่ไฟล์นั้นจะยังคงปรากฏในส่วนประมวลผลแล้วพร้อมเครื่องหมายเตือน และสามารถขยายดูคำสั่งซื้อที่ถูกปฏิเสธพร้อมเหตุผลได้
- ไฟล์จะไม่ถูกย้ายหรือเก็บเข้าคลัง แต่จะอยู่ในโฟลเดอร์ต่อไป และสถานะของไฟล์จะถูกบันทึกไว้ในฐานข้อมูล ไฟล์ที่ประมวลผลสำเร็จจะถูกลบโดยอัตโนมัติหลังจาก 90 วัน ส่วนไฟล์ในส่วนข้อผิดพลาดจะอยู่ต่อไปจนกว่าจะนำเข้าซ้ำหรือถูกลบ
- รูปแบบ XML ที่ชัดเจน (ฟิลด์ที่จำเป็น รูปแบบวันที่ ตรรกะวันในสัปดาห์) มีเอกสารอธิบายไว้ในคู่มือบนหน้าการตั้งค่าโดยตรง รวมถึงมีไฟล์ตัวอย่างให้ดาวน์โหลดได้
- การกำหนดค่านี้อยู่ในส่วนการตั้งค่า จึงสงวนไว้สำหรับบทบาทที่มีสิทธิ์ผู้ดูแลระบบเท่านั้น
