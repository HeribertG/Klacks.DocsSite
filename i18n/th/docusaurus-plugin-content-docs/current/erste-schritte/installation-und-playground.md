# การติดตั้งและ Playground

คุณสามารถลองใช้ Klacks ได้ภายในหนึ่งนาที และติดตั้งได้ภายในไม่กี่นาที ไม่ต้องลงทะเบียน ไม่ต้องคุยกับฝ่ายขาย

## Playground: พื้นที่ทดลองเพื่อทำความรู้จัก

Playground ไม่ใช่รูปแบบการติดตั้ง แต่เป็นอินสแตนซ์ Klacks สาธารณะที่มีข้อมูลตัวอย่างให้ทดลองเล่นได้โดยไม่ผูกมัด — ที่มาของชื่อก็มาจากตรงนี้ ใช้งานได้ที่ **[play.klacks-software.ch](https://play.klacks-software.ch)**:

- **เข้าสู่ระบบ:** `admin@test.com` · **รหัสผ่าน:** `P@ssw0rt1`
- คุณจะได้รับสิทธิ์ผู้ดูแลระบบเต็มรูปแบบ — ลองใช้ทุกฟีเจอร์ได้เลย
- ข้อมูลตัวอย่างมีลูกค้าราว 5'000 ราย และเป็นข้อมูลสาธิตล้วน
- **อย่ากรอกข้อมูลส่วนบุคคลจริง** ฐานข้อมูลจะถูกรีเซ็ตกลับเป็นสถานะคงที่ทุกวันเวลา 04:00 น. ตามเวลาสวิตเซอร์แลนด์ (02:00 UTC)

## การติดตั้ง: บนเซิร์ฟเวอร์ของคุณเอง (On-Premise)

แพ็กเกจ On-Premise มาพร้อมทุกอย่างที่จำเป็น: Docker images, ตัวติดตั้ง, ฐานข้อมูล, HTTPS และการอัปเดตอัตโนมัติ คุณดาวน์โหลดแพ็กเกจนี้ได้จาก [Klacks Store](https://klacks-software.ch/store/?culture=th) เท่านั้น

ใน Klacks Store เลือกอุตสาหกรรมได้หากต้องการ แล้วดาวน์โหลดไฟล์ ZIP สำหรับประเทศของคุณ ตัวติดตั้งจะสร้างรหัสผ่านและใบรับรองให้เอง ดาวน์โหลด Docker images เวอร์ชันล่าสุด และรอจนกว่าทุกอย่างจะทำงานได้

### Linux: ทีละขั้นตอน

คุณต้องมีเครื่องที่มี RAM อย่างน้อย 8 GB พอร์ต 80 และ 443 ที่ว่าง การเชื่อมต่ออินเทอร์เน็ต และบัญชีที่มีสิทธิ์ `sudo` ไม่จำเป็นต้องติดตั้ง Docker ไว้ก่อน (ดูขั้นตอนที่ 4)

1. **ดาวน์โหลด ZIP จาก Klacks Store** ที่หน้าของประเทศของคุณใน [Klacks Store](https://klacks-software.ch/store/?culture=th) พร้อมเลือกอุตสาหกรรมของคุณได้หากต้องการ
2. **แตกไฟล์ลงในโฟลเดอร์ถาวร** เช่น `~/klacks` ไม่ใช่ใน `Downloads` หรือ `/tmp` การอัปเดตอัตโนมัติจะทำงานกับโฟลเดอร์นี้โดยเฉพาะในภายหลัง หากโฟลเดอร์ถูกลบหรือย้าย การอัปเดตจะใช้งานไม่ได้ ตัวติดตั้งจะแจ้งเตือนหากรันจาก `Downloads` หรือ `/tmp`

   ```bash
   unzip 'klacks-onprem-*.zip' -d ~/klacks
   ```

3. **เปิดเทอร์มินัลในโฟลเดอร์นั้น** ในตัวจัดการไฟล์มักทำได้โดยคลิกขวาในโฟลเดอร์ (ชื่อเมนูขึ้นอยู่กับสภาพแวดล้อมเดสก์ท็อป) หรือพิมพ์ `cd ~/klacks`
4. **เริ่มตัวติดตั้ง:**

   ```bash
   sudo bash ./install-de.sh
   ```

   ในแพ็กเกจสำหรับเยอรมนี สคริปต์ชื่อ `install-de.sh` ส่วนในแพ็กเกจของประเทศอื่นจะมีรหัสประเทศอยู่ในชื่อ ดังนั้นโดยทั่วไปคือ `sudo bash ./install-*.sh` ตัวติดตั้งต้องใช้ `sudo` เพื่อให้เข้าถึง Docker และติดตั้งได้ตามความจำเป็น หากไม่ใช้ `sudo` จะทำได้ก็ต่อเมื่อติดตั้ง Docker ไว้แล้วและผู้ใช้ของคุณอยู่ในกลุ่ม `docker`

   **หากไม่มี Docker** ตัวติดตั้งจะเสนอให้ติดตั้ง Docker Engine ด้วยสคริปต์ทางการจาก `get.docker.com` ซึ่งจะเกิดขึ้นหลังจากถามคุณเท่านั้น (`[y/N]` ค่าเริ่มต้นคือ ไม่) และเฉพาะบน Ubuntu, Debian, Fedora, CentOS และ RHEL เครื่องต้องมี `curl` หรือ `wget` และการเชื่อมต่ออินเทอร์เน็ตด้วย บนดิสทริบิวชันอื่น ให้ติดตั้ง Docker Engine พร้อมปลั๊กอิน Compose ด้วยตัวเองตาม[คู่มือของ Docker](https://docs.docker.com/engine/install/) หากตัวติดตั้งทำงานโดยไม่มีเทอร์มินัล `INSTALL_DOCKER=yes` จะตอบคำถามนั้นว่าใช่ Docker เองไม่แนะนำสคริปต์นี้สำหรับการใช้งานจริง สำหรับเซิร์ฟเวอร์ที่ใช้งานจริง ควรติดตั้ง Docker ด้วยตัวเอง `docker-compose` รุ่นเก่า (เวอร์ชัน 1) ไม่รองรับ ต้องใช้ปลั๊กอิน `docker compose`
5. **รอสักครู่** ตัวติดตั้งจะสร้างรหัสผ่านและใบรับรองที่ลงนามด้วยตนเอง ดาวน์โหลด images และเริ่มสแตก ในการเริ่มต้นครั้งแรก API จะย้ายฐานข้อมูล (migrate) ตัวติดตั้งจะรอนานถึงสิบนาทีสำหรับขั้นตอนนี้ เมื่อเสร็จจะแสดง `Klacks is up at https://…` และด้านล่างเป็น**รหัสการตั้งค่าของคุณ** (`Your setup code` สิบสองอักขระในสามกลุ่ม กลุ่มละสี่ตัว) จดไว้ รหัสนี้อยู่ในไฟล์ `.env` ในโฟลเดอร์ติดตั้งด้วย โดยใช้ชื่อ `KLACKS_SETUP_CODE`
6. **เปิด Klacks:** `https://localhost` (หากใช้ชื่อเซิร์ฟเวอร์อื่นหรือพอร์ต HTTPS อื่น ให้ใช้ที่อยู่จากข้อความของตัวติดตั้ง) เบราว์เซอร์จะเตือนเรื่องใบรับรองที่ลงนามด้วยตนเอง ให้ยืนยันคำเตือน จากนั้นคุณสร้างบัญชีผู้ดูแลระบบของคุณเองด้วยรหัสการตั้งค่า ดู[การเข้าสู่ระบบครั้งแรก](#first-login)
7. **การอัปเดต**จากนั้นจะทำงานอัตโนมัติผ่านบริการอัปเดตที่มาพร้อมระบบ คุณไม่ต้องเริ่มตัวติดตั้งอีกครั้งเพื่อการนี้

หาก Docker เห็นหน่วยความจำน้อยกว่า 7 GiB การติดตั้งครั้งแรกจะหยุดลง วิธีตั้งค่าโฮสต์ที่เล็กกว่านี้อยู่ใน[ข้อกำหนดของระบบ](../betrieb/systemvoraussetzungen.md)

### Windows

บน Windows ให้เริ่ม `install-*.ps1` แทน `install-*.sh`

### ตัวเลือก: ชื่อเซิร์ฟเวอร์และโปรไฟล์ประเทศ

เมื่อใช้โปรไฟล์ประเทศ (ไม่บังคับ) ตัวติดตั้งจะตั้งค่าภาษา วันหยุด ขีดจำกัดชั่วโมงทำงาน ส่วนเพิ่ม และเทมเพลตอุตสาหกรรมให้ทันทีเมื่อเริ่มต้นครั้งแรก:

```bash
sudo SERVER_NAME=klacks.example.com REGION=de bash ./install.sh
```

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -ServerName klacks.example.com -Region de
```

บน Linux ให้ใส่ตัวแปร**หลัง** `sudo` เพราะโดยทั่วไป `sudo` จะไม่ส่งต่อตัวแปรที่อยู่ก่อนหน้ามันไปยังตัวติดตั้ง เมื่อใช้สคริปต์ของแพ็กเกจประเทศ คำสั่งจะเป็นดังนี้: `sudo SERVER_NAME=klacks.example.com bash ./install-de.sh`

แพ็กเกจประเทศจาก Klacks Store มีโปรไฟล์ของประเทศนั้นอยู่แล้ว สคริปต์ `install-*.sh` และ `install-*.ps1` ที่มาพร้อมแพ็กเกจจะตั้ง `REGION` หรือ `-Region` เป็นรหัสประเทศของแพ็กเกจให้อยู่แล้ว เช่น ในแพ็กเกจสำหรับเยอรมนีคือ `install-de.sh` และ `install-de.ps1` หากเรียก `install.sh` หรือ `install.ps1` โดยตรง `REGION` หรือ `-Region` ต้องเป็นรหัสประเทศนี้ หากไม่มี ตัวติดตั้งจะไม่ตั้งค่าโปรไฟล์ประเทศ

## พีซีสำนักงานที่ใช้ Windows: มีใน Microsoft Store ด้วย

สำหรับพีซีสำนักงานเครื่องเดียวที่ใช้ Windows มีตัวติดตั้งแยกต่างหากที่ทำงานได้โดยไม่ต้องใช้ Docker คุณรับได้จาก [Klacks Store](https://klacks-software.ch/store/?culture=th) ในหน้าของประเทศของคุณ และจาก [Microsoft Store](https://apps.microsoft.com/store/detail/XPFFW8HDX0KX26) (รายการ "Klacks") ด้วย ตัวติดตั้งในทั้งสองสโตร์เป็นตัวเดียวกัน เมื่อติดตั้งจาก Microsoft Store ตัวติดตั้งจะใช้ประเทศที่ตั้งค่าไว้ใน Windows โดยคุณไม่ต้องเลือกอุตสาหกรรมที่นั่น และหากประเทศนั้นไม่มีโปรไฟล์ประเทศ ตัวติดตั้งจะไม่ตั้งค่าโปรไฟล์ใดๆ การติดตั้งบนเซิร์ฟเวอร์ บน Docker และบน Linux ตลอดจนแพ็กเกจประเทศและอุตสาหกรรม มีให้เฉพาะใน Klacks Store เท่านั้น

บนพีซีสำนักงาน แม้จะติดตั้ง Klacks จาก Microsoft Store เวอร์ชันใหม่ก็ยังมาทาง การตั้งค่า > [การอัปเดตซอฟต์แวร์](../einstellungen/system-sicherheit/updates.md) ใน Klacks ไม่สามารถติดตั้งตัวติดตั้งที่ใหม่กว่าทับการติดตั้งที่มีอยู่ได้

## การเข้าสู่ระบบครั้งแรก: บัญชีผู้ดูแลระบบของคุณเอง {#first-login}

Klacks ที่เพิ่งติดตั้งยังไม่มีบัญชีของคุณ ดังนั้นเมื่อเปิดในเบราว์เซอร์ครั้งแรก จะแสดงหน้า "ตั้งค่าบัญชีผู้ดูแลระบบของคุณเอง" ทันที ก่อนการเข้าสู่ระบบใดๆ ได้แก่ ชื่อและนามสกุล ที่อยู่อีเมล (จะเป็นชื่อสำหรับเข้าสู่ระบบของคุณ) และรหัสผ่านที่กรอกสองครั้ง กฎของรหัสผ่านจะแสดงแบบเรียลไทม์อยู่ข้างๆ

บนเซิร์ฟเวอร์ (Docker) หน้านี้ต้องการ**รหัสการตั้งค่า**เพิ่มเติม แม้คุณจะเปิด Klacks ในเบราว์เซอร์บนเซิร์ฟเวอร์เครื่องนั้นเองก็ตาม ตัวติดตั้งแสดงรหัสนี้ไว้ตอนท้ายของการติดตั้ง และรหัสยังอยู่ในไฟล์ `.env` ในโฟลเดอร์ติดตั้งโดยใช้ชื่อ `KLACKS_SETUP_CODE` รหัสนี้ใช้ได้เฉพาะการตั้งค่าครั้งนี้ครั้งเดียว รหัสที่ผิดจะถูกปฏิเสธ ("รหัสการตั้งค่าไม่ตรงกัน โปรดตรวจสอบแล้วลองอีกครั้ง")

เมื่อคุณบันทึก บัญชีของคุณจะได้รับบทบาทผู้ดูแลระบบ และบัญชีทดสอบที่มาพร้อมระบบจะถูกปิดถาวรในขั้นตอนเดียวกัน จากนั้น Klacks จะเข้าสู่ระบบด้วยบัญชีของคุณเองให้อัตโนมัติ หากไม่สำเร็จ ให้เข้าสู่ระบบด้วยข้อมูลเข้าสู่ระบบใหม่ ตราบใดที่ยังตั้งรหัสการตั้งค่าอยู่ ก็ไม่สามารถใช้บัญชีทดสอบที่มาพร้อมระบบเพื่อเข้าสู่ระบบในเบราว์เซอร์ได้อยู่แล้ว ถัดไปจะเป็นหน้า "ประเทศและอุตสาหกรรม"

จนกว่าจะสร้างบัญชีของคุณเอง เซิร์ฟเวอร์จะบล็อกการเรียกอื่นทุกรายการด้วยรหัสข้อผิดพลาด `SETUP_REQUIRED` (HTTP 403) เบื้องหลังไม่ใช่ความขัดข้อง เพียงแต่ยังขาดการตั้งค่าเท่านั้น

- บนพีซีสำนักงานที่ใช้ Windows คุณไม่ต้องใช้รหัสการตั้งค่า หากเปิด Klacks ในเบราว์เซอร์บนพีซีเครื่องเดียวกัน จากเครื่องอื่นจะแสดงเฉพาะหน้าเข้าสู่ระบบ
- หาก Klacks แสดงหน้าเข้าสู่ระบบแทน เช่น ในการติดตั้งที่ไม่มีรหัสการตั้งค่า ผลลัพธ์ของตัวติดตั้งจะระบุบัญชีที่มาพร้อมระบบ ในกรณีนั้น Klacks ก็จะพาคุณไปสร้างบัญชีผู้ดูแลระบบของคุณเองทันทีเช่นกัน
- หากสองคนส่งพร้อมกัน จะมีเพียงคนแรกเท่านั้นที่เป็นผู้ดูแลระบบ คนที่สองจะไปอยู่ที่หน้าเข้าสู่ระบบ

ด่านนี้ถูกปิดโดยตั้งใจเฉพาะใน Playground และในสภาพแวดล้อมพัฒนาในเครื่องเท่านั้น ที่นั่นบัญชีที่มาพร้อมระบบจะยังคงอยู่

## ข้อมูลที่ควรทราบ

- **ข้อกำหนด:** RAM อย่างน้อย 8 GB และ 4 vCPU, Docker พร้อม Compose v2 (บน Linux ตัวติดตั้งจะติดตั้ง Docker ให้หลังจากถามคุณ), พอร์ต 80 และ 443 ที่ว่าง และการเข้าถึง HTTPS ขาออกไปยัง `ghcr.io` และ `github.com` รายละเอียดและตัวอย่างการคำนวณสำหรับโฮสต์ที่เล็กกว่าอยู่ใน[ข้อกำหนดของระบบ](../betrieb/systemvoraussetzungen.md)
- บริการอัปเดตที่มาพร้อมระบบจะทำให้การติดตั้งของคุณทันสมัยอยู่เสมอโดยอัตโนมัติ — พร้อมสำรองข้อมูลก่อนการอัปเดตทุกครั้งและย้อนกลับอัตโนมัติหากเกิดปัญหา รายละเอียดการทำงานอยู่ใน[การอัปเดตและการย้อนกลับ](../betrieb/updates-und-rollback.md)
- ข้อมูลของคุณอยู่ในฐานข้อมูลของคุณเองบนโครงสร้างพื้นฐานของคุณ อย่างไรก็ตาม บางฟังก์ชันจะเรียกบริการภายนอก — บริการใดบ้างอยู่ในหัวข้อถัดไป
- การเรียกตัวติดตั้งอีกครั้งไม่เป็นอันตราย แต่ไม่ใช่การอัปเดต ตัวติดตั้งจะคงรหัสผ่าน ใบรับรอง และเวอร์ชันที่กำหนดไว้ตอนติดตั้งครั้งแรก แล้วเริ่มสแตกใหม่ (บน Linux ให้ใช้ `sudo` อีกครั้ง หากคุณติดตั้งครั้งแรกด้วย `sudo`) วิธีนี้ใช้ซ่อมสแตกที่หยุดทำงาน เวอร์ชันใหม่จะติดตั้งโดยบริการอัปเดต ไม่ใช่ตัวติดตั้ง
- หากคุณมีใบรับรองของตัวเอง ให้วาง `server.crt` และ `server.key` ไว้ใน `nginx/certs/` ในโฟลเดอร์ติดตั้งก่อนการติดตั้ง มิฉะนั้นตัวติดตั้งจะสร้างใบรับรองที่ลงนามด้วยตนเอง
- คุณต้องสำรองฐานข้อมูลของคุณเองอย่างสม่ำเสมอ — วิธีทำอยู่ใน[การสำรองและการกู้คืน](../betrieb/backup-und-wiederherstellung.md)

## บริการภายนอกที่ Klacks เรียกใช้

ข้อมูลของคุณอยู่บนเซิร์ฟเวอร์ของคุณ อย่างไรก็ตาม สำหรับบางฟังก์ชัน Klacks จะเรียกบริการสาธารณะบนอินเทอร์เน็ตในการใช้งานมาตรฐาน ที่อยู่ของบริการเหล่านี้ฝังตายตัวอยู่ในระบบ ขณะนี้คุณไม่สามารถกรอกเซิร์ฟเวอร์ Geocoding เซิร์ฟเวอร์เส้นทาง หรือเซิร์ฟเวอร์แผนที่ของคุณเองได้

| บริการ | ใช้ทำอะไร | ข้อมูลที่ส่ง | ค่าเริ่มต้น | วิธีปิด |
|---|---|---|---|---|
| Nominatim ของ OpenStreetMap (`nominatim.openstreetmap.org`) | แปลงที่อยู่เป็นพิกัด: เมื่อบันทึกที่อยู่ สำหรับที่ตั้งบริษัท ในการวางแผนเส้นทาง และในบริการเบื้องหลังสำหรับที่อยู่และที่ตั้งของกลุ่ม | ถนน รหัสไปรษณีย์ เมือง และประเทศ โดยไม่มีชื่อบุคคล สำหรับที่ตั้งของกลุ่มคือชื่อสถานที่หรือชื่อกลุ่ม | เปิด | `BackgroundServices__AddressGeocoding=false` และ `BackgroundServices__GroupGeocoding=false` ปิดเฉพาะบริการเบื้องหลัง เมื่อบันทึกที่อยู่ ระบบยังคงทำ Geocoding อยู่ |
| เซิร์ฟเวอร์ OSRM สาธารณะ (`router.project-osrm.org`) | เวลาเดินทาง ระยะทาง และเส้นทางบนแผนที่ | พิกัดของสถานที่ปฏิบัติงาน โดยไม่มีชื่อ | เปิด ตราบใดที่ยังไม่ได้ระบุคีย์ OpenRouteService นอกจากนี้ เบราว์เซอร์จะสอบถาม OSRM โดยตรงเมื่อเซิร์ฟเวอร์ Klacks ไม่ส่งเส้นทางกลับมา | ไม่มีให้เลือก |
| OpenRouteService (`api.heigit.org`) | เหมือน OSRM และเพิ่มจักรยานกับการเดินเท้า | พิกัดของสถานที่ปฏิบัติงาน โดยไม่มีชื่อ | เฉพาะเมื่อระบุคีย์ API ไว้ | ลบคีย์ที่ การตั้งค่า > OpenRoute |
| แผนที่แบบไทล์ (OpenStreetMap, OpenStreetMap.de หรือ CARTO) | การแสดงแผนที่ในแดชบอร์ด | จากเบราว์เซอร์: ที่อยู่ IP และส่วนของแผนที่ที่แสดง | เปิด เมื่อมีการแสดงแผนที่ | เลือกผู้ให้บริการได้ในแผนที่ แต่ใช้เซิร์ฟเวอร์ไทล์ของคุณเองไม่ได้ |
| GitHub (`github.com`) และ GitHub Container Registry (`ghcr.io`) | การติดตั้งและการอัปเดตอัตโนมัติ: manifest ของรุ่นและ Docker images | คำขอดาวน์โหลดปกติ ไม่มีข้อมูลการวางแผน | เปิด | — |
| Klacks Marketplace (`klacks-software.ch/store`) | แพ็กเกจภาษาและประเทศ | รหัสประเทศ รหัสแพ็กเกจ หรือคำค้นหา | เมื่อค้นหาแพ็กเกจและเมื่อโหลดโปรไฟล์ประเทศ | กำหนดที่อยู่ได้ผ่าน `LanguagePlugins__MarketplaceUrl` |
| Hugging Face (`huggingface.co`) | ดาวน์โหลดครั้งเดียวสำหรับโมเดลค้นหาของ Klacksy | ไม่มีข้อมูลลูกค้า (ดาวน์โหลดไฟล์) | เมื่อต้องใช้ครั้งแรก | — |
| Open-Meteo (`api.open-meteo.com`, `air-quality-api.open-meteo.com`) | ข้อมูลสภาพอากาศและคุณภาพอากาศในวิดเจ็ตต้อนรับ การสอบถามสภาพอากาศผ่าน Klacksy | พิกัดของเบราว์เซอร์ (หากอนุญาต) หรือที่ตั้งบริษัท | เปิด | `Assistant__Ambient__Enabled=false` ปิดเฉพาะข้อมูลคุณภาพอากาศและวันหยุด ไม่ปิดการสอบถามสภาพอากาศของข้อความต้อนรับ |
| Nager.Date (`date.nager.at`) | ข้อมูลวันหยุดในวิดเจ็ตต้อนรับ | รหัสประเทศ | เปิด | `Assistant__Ambient__Enabled=false` |
| ผู้ให้บริการ AI บนคลาวด์ (เช่น OpenAI, Anthropic, Google, DeepSeek) | Klacksy และฟังก์ชันเบื้องหลังที่ใช้ AI (เช่น การจัดประเภทที่ตั้งของกลุ่ม) | คำขอพร้อมบริบทที่จำเป็นจากข้อมูลของคุณ | เฉพาะเมื่อกำหนดค่าโมเดลคลาวด์ไว้ | ใช้โมเดลภายในเครื่อง |
| บริการเสียง ค้นหา และแปลภาษา (เช่น Deepgram, Groq, AssemblyAI, Edge TTS, OpenAI TTS, ElevenLabs, Google Cloud TTS, DeepL, การค้นหาเว็บ) | การป้อนและการส่งออกเสียง การค้นหาเว็บ การแปลภาษา | เสียงหรือข้อความ | เฉพาะเมื่อใช้งานหรือกำหนดค่าไว้ การรู้จำเสียงของเบราว์เซอร์ทำงานผ่านบริการออนไลน์ของเบราว์เซอร์นั้น ขึ้นอยู่กับเบราว์เซอร์ | ไม่ใช้ฟังก์ชันนั้น |

สวิตช์ในคอลัมน์ "วิธีปิด" เป็นตัวแปรสภาพแวดล้อมของคอนเทนเนอร์ `klacks-api` ให้ใส่ไว้ใน `docker-compose.yml` ใต้ `environment:` ของบริการนี้ การใส่ในไฟล์ `.env` อย่างเดียวไม่พอ เพราะบริการไม่อ่านไฟล์นั้นเป็น `env_file`

เมื่อใช้โมเดล AI ภายในเครื่อง จะไม่มีคำขอไปยังโมเดลภาษาถูกส่งไปยังผู้ให้บริการ AI ภายนอก สำหรับบริการอื่นในตารางนี้ สิ่งนี้ไม่ได้เปลี่ยนแปลงอะไร
