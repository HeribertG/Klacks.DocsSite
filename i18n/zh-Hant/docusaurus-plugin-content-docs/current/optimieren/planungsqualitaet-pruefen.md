# 檢查排班品質：違規、缺口與被跳過的項目

排班助理執行完一輪之後，Klacks 會在結果旁附上三張診斷表格：排班在哪裡牴觸了規則、哪裡缺少資格，以及哪些項目根本沒有被排入。

## 運作方式

這三份報告出現在各個排班助理自己的對話方塊中 — 而不是在排班網格裡。它們屬於助理執行結果的一部分，僅管理員可見，因為整體而言自動排班需要管理員角色。每份報告的標題都會標示其條目數量，而且**如果沒有找到任何項目，就根本不會顯示** — 因此沒看到某個區塊，就是好消息。

**如何開啟這些對話方塊：** 排班表中的魔杖按鈕，在預設狀態下會直接啟動一次排班，不會顯示任何對話方塊。管理員按下 **Ctrl+Shift+H**，即可將此按鈕切換為下拉選單，列出各個排班助理（Plan、Fuzzy Harmonizer、Holistic Harmonizer、Background Optimizer、Recovery）— 唯有透過這個下拉選單，才會開啟包含診斷表格的對話方塊。

**資格缺口**會與結果一併出現，也就是在您採用*之前*。欄位包括：嚴重程度、班次、日期、所需資格、原因 — 一旦至少有一列指出了某個人，還會多出「員工」欄位。原因欄會顯示*不具備*、*已過期*或*等級不足*。背後有兩種不同情況：要麼某個班次職缺始終空缺，因為沒有任何有空的人具備所需資格 — 此時該列不會指名任何人；要麼某人留在了他不具備資格的班次上 — 此時會列出其姓名。如果只是系統中缺少該資格的記錄，請在該員工的資料中補上；[資格目錄](../einstellungen/stammdaten-organisation/qualifikationen.md)說明了如何維護資格。否則，請改排其他人，或調整該班次的要求。

**合規違規**會在您採用結果*之後*才出現。欄位包括：日期、員工、備註；備註會以白話文說明所違反的規則，並附上具體數值。紅色列代表錯誤，黃色代表警告與提示。對於兩個 Harmonizer 助理而言，報告只會顯示新情境相較於實際排班表**額外**帶來的內容 — 並註明其中有多少違規是以封鎖模式管理的。這類違規會阻止情境被採用，除非先解決，或由有權限的人明確覆寫。

**被跳過的排班**只出現在負責排班的助理中，同樣是在採用之後才出現 — 而且全部以紅色顯示。欄位包括：日期、員工、班次、原因。這裡列出的不是已排定的內容，而是 Klacks 刻意**沒有**寫入的內容：那些原本會違反封鎖模式規則的指派。原因會以簡短分類呈現（「休息時間太短」、「連續工作天數過多」、「時間衝突」……）。視情況而定，Klacks 會為有權限的人提供以 Override 方式仍然採用該次執行結果的選項；其餘人則會收到提示，請以啟用 Override 的方式重新執行助理，或請有權限的人協助處理。每一次 Override 都會被記錄。

會檢查哪些規則、以及規則的嚴格程度，由您在[排班規則](../planen/planungsregeln.md)中設定；排班表究竟如何產生，則說明於[自動排班：一鍵啟動，其餘在背景執行](../planen/auto-planung.md)。

## 小提醒

- 被封鎖的條目不會導致整份排班表被捨棄：只有受影響的指派會被移除，同一人其餘沒有問題的條目仍會照常寫入。
- 資格缺口的嚴重程度遵循一個簡單原則：只有當標記為必要的資格完全不具備時，才會顯示為**錯誤**。已過期的資格、等級不足，以及任何選填的要求，都只會顯示為**警告**。
- 空缺的班次職位只有在真的沒有任何有空的人選符合資格時，才會出現在資格缺口中。若是因為其他原因而空缺，則屬於一般的人力不足，不會在這裡被回報。
- 若自動排班以整體執行的方式進行，Klacks 只會以簡短提示顯示結果，並附上資格缺口的數量 — 詳細的表格則屬於各個助理自己的對話方塊。
- 這些報告純粹是檢視用途：無法編輯，也不會改變任何內容。修正動作要在[排班網格：您的互動式時間矩陣](../planen/plan-raster.md)中進行，或是重新執行一次助理。
