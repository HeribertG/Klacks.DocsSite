# アップデートとロールバック

Klacksは自分自身を更新します — 署名付きパッケージを使い、各ステップの前にバックアップを取り、問題があれば自動で元に戻します。このページでは、その間に何が起きるか、そしてどう介入できるかを説明します。

## アップデートの流れ

1. **検出。** APIは、開発元がリリースごとに公開する署名付きマニフェストを取得します。そこにより新しいバージョンが記載されていれば、アップデートが利用可能と判断されます。
2. **バックアップ。** アップデートサービスはデータベースのバックアップを作成します。新しいバージョンにマイグレーションが含まれる場合、このバックアップはアップデート操作に固定的に紐づけられ、後でロールバックのために使えるよう保持されます。
3. **取得と同時有効化。** サービスは`klacks-api`**と**`klacks-ui`の新しいイメージを取得し、両方をまとめて切り替えます — 2つの部品は常に歩調を合わせ、異なるバージョンで動くことはありません。
4. **確認。** 切り替え後、サービスは詳細ヘルスチェック`/internal/health/deep`を呼び出します。
5. **評価。** 新しいバージョンが正常なら、アップデートは成功とみなされます。そうでなければ、サービスは**両方の**部品を自動的に前のバージョンへ戻し、再度確認します。それも成功しない場合は、見落とされないよう失敗として記録されます。

## 「署名付き」とは

開発元はすべてのリリースに署名し、お客様のKlacksはパッケージを受け入れる前にその署名を検証します。公開鍵とマニフェストのアドレスは、`.env`に入っている開発元固定の値です:

- `UPDATE_MANIFEST_BASE_URL` — 開発元のリリース配布元に固定
- `UPDATE_SIGNATURE_PUBLIC_KEY` — 開発元が署名に使う秘密鍵と対応している必要があります

この2つの値は**変更を想定していません**。差し替えると検証が無効になり、署名が塞いでいるはずの穴をまさに開けてしまいます。

マニフェストには、とりわけ次の項目が含まれます: チャンネル(`Stable`または`Beta`)、最新バージョン、直接アップデートが可能な最小バージョン(`MinUpgradableFrom`)、公開日、データベースのマイグレーションを含むかどうか、成果物、署名、変更履歴へのリンク。

`klacks-api`と`klacks-ui`は、気づかないうちにずれていかないよう、`.env`で**正確なバージョンに固定**されています。アップデートサービス自身は常に`latest`で動きます — 意図的に署名付きマニフェストの対象外で、更新するのはapiとuiだけです。

## 運用中の設定

管理者向け領域の**システム → アップデート**で:

| 設定 | 効果 |
|---|---|
| **自動アップデートを有効化** | アップデートを検出し、自動的に適用します |
| **通知のみ** | アップデートは**検出**されるだけで、手動で実行するまで適用されません |
| **メンテナンスウィンドウ** | 自動アップデートの実行が許される時間帯 |

これらの設定はデータベースに保存され、`.env`の初期値(`UPDATE_AUTO_ENABLED`、`UPDATE_NOTIFY_ONLY`)よりも優先されます。後者は初回起動時にしか効きません。

## 手動でロールバックする

自動の場合は誰も介入する必要がありません — 失敗したアップデートは、サービスが自分で元に戻します。あえて1つ前に戻したい場合は:

1. `.env`の`KLACKS_API_TAG`と`KLACKS_UI_TAG`を、前のバージョンに設定します。
2. スタックを再度有効化します: `docker compose up -d klacks-api klacks-ui`。
3. **不具合のあるバージョンがすでにマイグレーションを実行していた場合は**、アップデート前の該当バックアップも書き戻してください — その際は[バックアップと復元](../backup-und-wiederherstellung/)ページの落とし穴に注意してください: 新しいバージョンが作成したテーブルは書き戻し後も残り、次の起動を妨げます。

## 知っておくと良いこと

- **ロールバックは非常手段ではなく、通常の流れです。** すべてのアップデート操作にはステータスがあります: 成功、ロールバック済み、またはロールバック失敗。ロールバックされたアップデートは、記録される通常の操作であり — 異常事態ではありません。
- **ロールバックされたアップデートは、リセットされたアップデートではありません。** ロールバックが戻すのはバージョンであって、お客様のデータではありません。アップデートからロールバックまでの間に行ったデータの変更は、バックアップ時点の状態から取り込まれます。
- **確認はログで行えます:** `docker compose logs klacks-updater`で、検出、バックアップ、切り替え、ロールバックが表示されます。
