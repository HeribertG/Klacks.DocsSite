# 勤務のライフサイクル: 注文からセグメントまで

勤務がそもそも配置される前に、それは4つの段階を経ます — 自由に編集できる注文から、変更不能な封印済み注文、計画可能な勤務、そしてそのセグメントへと進みます。その狙いはこうです: 合意された内容は、その後もずっと読み返せる形で残る一方、日々の運用がその後に再計画する部分は、それでも柔軟に動かせる、というものです。

勤務は必ずしも注文と結びついているわけではありません — Klacksは、顧客に紐づかない社内の定期的な勤務も、多数の配送を伴う複雑な注文も、複数のコンテナ部分に分割された業務も、同様に扱うことができます。

## 仕組み

**1. 注文 — 自由に編集可能。** 新しい勤務はすべてここから始まります。勤務ページでは、**+ 新規注文**ボタンをクリックすると入力画面が開きます。注文は何度でも編集でき、すべての項目が入力可能です。まだ勤務表には表示されず、そのため従業員を割り当てて計画することもできません。とはいえ単なる下書きではありません — これは正真正銘の注文であり、ただまだ封印されていないだけです。勤務リストでは、Klacksはこの段階を**注文**の下に表示します。そこで**計画可能な勤務**タブに切り替えると、ボタンは**+ 新しい勤務**という表示になります: このボタンは、顧客と紐づかない注文を作成します — 外部から誰も発注・支払いをしない一般業務のためのものです。その場合、*住所*カードはなくなりますが、この勤務も同じ4段階を経ます。

**2. 封印済み注文 — 変更不能。** 注文の内容が確定したら、*基本情報*カードの鍵アイコンのボタンで封印します。この瞬間から注文はロックされ、合意内容の拘束力ある写しとして永続的に保持されます — たとえその後、日々の運用でこの勤務がとっくに再計画されていたとしてもです。保存後は**元に戻せません**。どの注文が既にこの段階に達しているかは、勤務リストの**封印済みの注文のみ表示**チェックボックスで確認できます。

**3. 計画可能な勤務 — ここで計画します。** 封印すると、一度きり、一気に計画可能な勤務が生成されます: 注文にひも付いたコピーです。この勤務だけが[プラン・グリッド: あなたの対話型タイム・マトリックス](../planen/plan-raster.md)に表示され、この勤務にだけ従業員を予約でき — しかも編集可能なままです。その後もう一度保存しても、2つ目のコピーが作られることはありません。勤務リストでは**計画可能な勤務**の下に表示されます。

**4. セグメント — 切り分けられた勤務。** 計画可能な勤務は、日単位や時間帯単位など、切り分けることができます。それまでの勤務自体が1つのセグメントになり、その隣にさらにセグメントが生まれます。すべてのセグメントは同様に計画可能で、実際の配置を担うのはこれらのセグメントです。封印済み注文はこれに一切影響されません — それは背景にある契約であり続けます。

**鍵ボタンが有効になるタイミング:** このボタンは、注文が計画に十分な情報を備えるまでグレー表示のままです — 略称、名称、開始日が入力され、少なくとも1つの曜日と少なくとも1つのグループが選択され、シフトあたりの作業数と人数の両方がゼロより大きい必要があります。ツールチップにはこう明記されています: 「ロック後、注文は変更不能になり、計画の準備が整います」。

**変更不能性のただ一つの例外:** 封印済み注文に終了日がない場合 — 例えば注文が継続的に延長されている、または終了時期がまだ未定であるためなど — この1項目だけは後からでも設定できます。条件: 選択した日付以降、まだ勤務が計画されていないことです。それ以降は、この項目も他のすべての項目と同様にロックされます。

**例:** 5月1日に「ミュラー家の結婚式」という注文を入力し、2日間かけて内容を詰めていきます。5月3日、顧客が確定を伝えたので封印します。Klacksは注文を確定させ、同時に計画可能な勤務を作成します。5月4日、配置担当者が2名の従業員を登録し、5月5日には勤務が2つのセグメントに切り分けられます。6月1日に期間が締められ、セグメント上のエントリーはロックされます。5月3日に封印された注文は、この間一度も変更されていません。

**入力画面のカード構成。** 入力画面は個別に開閉できるカードで構成されており、保存と破棄は作業領域の下部にある保存バーで行います。一部のカードは、*基本情報*カードで**エキスパートモード**スイッチをオンにした場合にのみ表示されます:

- **基本情報** — 略称(最大6文字。名称を入力すると、Klacksが自動的に候補を提案します)、名称、開始日・終了日、およびメモです。鍵ボタンとエキスパートモードのスイッチもここにあります。
- **グループ** — 勤務を1つまたは複数のグループに割り当てます。少なくとも1つのグループが必須で、選択されていない間は情報ボックスがその旨を示します。
- **必要資格** — 勤務が求める[資格](../einstellungen/stammdaten-organisation/qualifikationen.md)を、それぞれ最低レベル(低いからエキスパートまで)と必須かどうかの指定とともに設定します。
- **時間と曜日** — 開始時刻、終了時刻、所要時間、そして勤務が発生する曜日、さらに2つの祝日ルールです。エキスパートモードでは、勤務を時間枠として設定することもできます: その場合、開始時刻と終了時刻の間の枠内で柔軟に位置し、カウントされるのは入力された所要時間です。
- **マクロ**(エキスパートモード) — 所要時間と給与の計算のために、勤務を[マクロ](../einstellungen/klacksy-konfiguration/makros.md)に紐づけます。
- **住所** — 顧客または勤務場所を、名称またはID番号で検索します。右側のフィルター列で、この検索をさらに絞り込めます。
- **特別な特徴**(エキスパートモード) — 周期性を伴う散発的な勤務、ブリーフィングとデブリーフィング、往復の移動時間、そしてシフトあたりの従業員数と作業数です。
- **標準経費**(エキスパートモード) — この勤務で定期的に発生する経費を、名称・金額・課税対象かどうかとともに設定します。

計画可能な勤務がその後どのように配置されるかは、[自動計画: ワンクリック、あとはバックグラウンド任せ](../planen/auto-planung.md)と[プラン・グリッド: あなたの対話型タイム・マトリックス](../planen/plan-raster.md)で説明しています。

## 知っておくと良いこと

- **ここでの「封印」は、承認ワークフローにおける「封印」とは意味が異なります。** 注文の封印が固定するのは、勤務の*内容*です — 何をすべきかという情報が、恒久的に固定されます。これに対して[承認ワークフロー: 下書きから確定プランへ](../planen/freigabe-workflow.md)と[期間締め](../planen/periodenabschluss.md)がロックするのは、*具体的な日付ごとのエントリー*です。両者は互いに独立して機能します。
- **注文は自動的にも作成されます。** 入力画面のほかに、[ERPインポート](../einstellungen/kommunikation-integration/erp-uebernahmepunkte.md)がもう一つの経路です: そこから届く注文も、まずは未封印の注文として届き、確認して封印する必要があります。
- **忘れられた注文は知らせが来ます。** 注文が開始直前になっても未封印のままだと、[自発的なチームメンバーとしてのKlacksy](../ki/klacksy-proaktiv.md)が気づきの種類「未封印の注文」でそれを知らせます — 未封印であることは、計画不能であることを意味するからです。
- **コンテナ勤務は少し異なる動きをします。** コンテナとは、複数の部分勤務をまとめる入れ物です。そのため顧客も住所も持たず、*住所*カードと*標準経費*カードはなくなります。*特別な特徴*カードには、散発的な勤務のオプションのみが表示されます。「コンテナである」チェックボックスはエキスパートモードの*基本情報*カードにあり、注文がまだ未封印である間のみ設定できます。
- **散発的な勤務と時間枠勤務はカウントされません。** どちらも、固定的な日次の必要人数を表すものではないため、意図的に[リソース・モニター](../optimieren/ressourcen-monitor.md)の勤務バーには表示されません。
