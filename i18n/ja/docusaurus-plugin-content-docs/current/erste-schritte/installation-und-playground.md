# インストールとPlayground

Klacksは1分で試すことができ、数分でインストールできます。登録も、営業トークも不要です。

## Playground: 気軽に試せる遊び場

Playgroundはインストール方法の一つではなく、気軽に触って試せるサンプルデータ入りの公開Klacksインスタンスです — この名前の由来もそこにあります。**[play.klacks-software.ch](https://play.klacks-software.ch)**で稼働しています。

- **ログイン:** `admin@test.com` ・ **パスワード:** `P@ssw0rt1`
- フル管理者権限を持っているので、何でも試すことができます。
- サンプルデータには約5'000件のクライアントが含まれており、すべてデモ用のデータです。
- **実在する個人データは入力しないでください。** データベースは毎日、スイス時間の04:00(UTC 02:00)に決まった状態へリセットされます。

## インストール: 自社サーバーで(オンプレミス)

オンプレミスパッケージには、Dockerイメージ、インストーラー、データベース、HTTPS、自動アップデートまで、すべてが含まれています。このパッケージは[Klacks Store](https://klacks-software.ch/store/?culture=ja)でのみ入手できます。

Klacks Storeで必要に応じて業種を選び、貴社の国向けのZIPをダウンロードしてください。インストーラーがパスワードと証明書を自動生成し、最新のDockerイメージを取得して、すべてが稼働するまで待機します。

### Linux: ステップごとの手順

RAMが8 GB以上で、ポート80と443が空いており、インターネットに接続でき、`sudo`権限を持つアカウントがあるマシンが必要です。Dockerを事前にインストールしておく必要はありません(手順4を参照)。

1. **ZIPをKlacks Storeからダウンロードします。** [Klacks Store](https://klacks-software.ch/store/?culture=ja)の貴社の国のページから、必要に応じて業種を指定してダウンロードします。
2. **固定のフォルダーに展開します。** たとえば`~/klacks`にし、`Downloads`や`/tmp`は避けてください。自動アップデートは後でまさにこのフォルダーを使って動作するため、削除または移動すると動作しなくなります。インストーラーが`Downloads`や`/tmp`で実行されている場合は、警告を表示します。

   ```bash
   unzip 'klacks-onprem-*.zip' -d ~/klacks
   ```

3. **フォルダー内でターミナルを開きます。** ファイルマネージャーでは、たいていフォルダー内での右クリックで開けます(表示名はデスクトップ環境によって異なります)。または`cd ~/klacks`と入力します。
4. **インストーラーを起動します:**

   ```bash
   sudo bash ./install-de.sh
   ```

   ドイツ向けパッケージではスクリプト名は`install-de.sh`です。他の国のパッケージでは、その国のコードが名前に入るため、一般には`sudo bash ./install-*.sh`となります。インストーラーがDockerを操作し、必要に応じてインストールできるようにするため、`sudo`が必要です。`sudo`なしで実行できるのは、Dockerがすでにインストールされていて、ユーザーが`docker`グループに属している場合だけです。

   **Dockerがない場合**、インストーラーは`get.docker.com`の公式スクリプトでDocker Engineをインストールするかどうかを確認します。これは確認(`[y/N]`、デフォルトはNo)に同意した場合のみ行われ、Ubuntu、Debian、Fedora、CentOS、RHELに限られます。そのためには、マシンに`curl`または`wget`とインターネット接続が必要です。他のディストリビューションでは、[Dockerのガイド](https://docs.docker.com/engine/install/)に従って、Docker EngineをComposeプラグインとともに自分でインストールしてください。インストーラーをターミナルなしで実行する場合は、`INSTALL_DOCKER=yes`で確認に「はい」と答えたことになります。Docker自身は、このスクリプトを本番運用には勧めていません。本番サーバーでは、Dockerを自分でインストールすることをお勧めします。古い`docker-compose`(バージョン1)はサポートされておらず、`docker compose`プラグインが必要です。
5. **待ちます。** インストーラーがパスワードと自己署名証明書を生成し、イメージを取得して、スタックを起動します。初回起動時にAPIがデータベースをマイグレーションするため、インストーラーは最大10分待機します。最後に`Klacks is up at https://…`と表示され、その下に**セットアップコード**(`Your setup code`、4文字ずつ3グループの12文字)が表示されます。これを控えておいてください。インストールフォルダー内の`.env`ファイルにも`KLACKS_SETUP_CODE`として記載されています。
6. **Klacksを開きます:** `https://localhost`(別のサーバー名やHTTPSポートの場合は、インストーラーのメッセージに表示されたアドレス)。ブラウザーが自己署名証明書について警告しますので、警告を承認してください。その後、セットアップコードを使って自分の管理者アカウントを作成します。[初回ログイン](#first-login)を参照してください。
7. **アップデート**はその後、付属のアップデートサービスが自動的に行います。そのためにインストーラーを再度起動する必要はありません。

Dockerが利用できるメモリが7 GiB未満の場合、初回インストールは中止されます。より小さいホストの設定方法は、[システム要件](../betrieb/systemvoraussetzungen.md)を参照してください。

### Windows

Windowsでは、`install-*.sh`の代わりに`install-*.ps1`を実行します。

### オプション: サーバー名と国別プロファイル

任意で国別プロファイルを指定すると、インストーラーは初回起動時に、言語、祝日、労働時間の上限、割増、業種テンプレートを自動的に設定します:

```bash
sudo SERVER_NAME=klacks.example.com REGION=de bash ./install.sh
```

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -ServerName klacks.example.com -Region de
```

Linuxでは、変数は`sudo`の**後ろ**に置きます。`sudo`は、前に置かれた変数を通常はインストーラーに引き継ぎません。国別パッケージのスクリプトを使う場合、呼び出しは次のようになります: `sudo SERVER_NAME=klacks.example.com bash ./install-de.sh`。

Klacks Storeの国別パッケージには、その国のプロファイルが含まれています。同梱の`install-*.sh`と`install-*.ps1`は、`REGION`または`-Region`をすでにその国のコードに設定済みです。たとえばドイツ向けパッケージでは`install-de.sh`と`install-de.ps1`です。`install.sh`または`install.ps1`を直接呼び出す場合は、`REGION`または`-Region`にその国のコードを指定する必要があります。指定しないと、インストーラーは国別プロファイルを設定しません。

## Windowsのオフィス用PC: Microsoft Storeでも入手可能

Windowsのオフィス用PC 1台向けに、Dockerなしで動作する専用のセットアップがあります。[Klacks Store](https://klacks-software.ch/store/?culture=ja)のお住まいの国のページと、[Microsoft Store](https://apps.microsoft.com/store/detail/XPFFW8HDX0KX26)(「Klacks」)で入手できます。どちらのストアでも同じセットアップです。Microsoft Storeからインストールした場合は、Windowsで設定されている国が適用されます。業種はそこでは選択せず、その国の国別プロファイルがない場合、セットアップはプロファイルを設定しません。サーバー、Docker、Linuxへのインストール、および国別・業種別パッケージはKlacks Storeでのみ入手できます。

オフィス用PCでは、新しいバージョンはKlacksの「設定 > [ソフトウェアアップデート](../einstellungen/system-sicherheit/updates.md)」から適用します。KlacksをMicrosoft Storeからインストールした場合も同じです。既存のインストールに新しいセットアップを上書きインストールすることはできません。

## 初回ログイン: ご自身の管理者アカウント {#first-login}

インストールしたばかりのKlacksには、まだご自身のアカウントがありません。そのため、ブラウザーで最初に開くと、ログインよりも前に、「ご自身の管理者アカウントを設定」ページが表示されます。姓名、メールアドレス(ログイン名になります)、そして2回入力するパスワードを入力します。パスワードの条件は、横にリアルタイムで表示されます。

サーバー(Docker)では、このページは追加で**セットアップコード**を求めます。サーバー自体のブラウザーでKlacksを開く場合も同様です。コードはインストールの最後にインストーラーが表示したもので、インストールフォルダー内の`.env`ファイルにも`KLACKS_SETUP_CODE`として記載されています。このコードは、この1回のセットアップにのみ有効です。コードが間違っていると拒否されます(「セットアップコードが一致しません。確認してもう一度お試しください。」)。

保存すると、アカウントに管理者ロールが付与され、同梱のテストアカウントは同じ処理の中で完全に無効化されます。その後、Klacksは自動的にご自身のアカウントでログインします。失敗した場合は、新しい認証情報でログインしてください。セットアップコードが設定されている間は、同梱のテストアカウントはそもそもブラウザーからのログインに使えません。次に「国と業種」ページが続きます。

ご自身のアカウントが作成されるまで、サーバーはそれ以外のすべてのリクエストをエラーコード`SETUP_REQUIRED`(HTTP 403)でブロックします。これは障害ではありません。セットアップがまだ済んでいないだけです。

- Windowsのオフィス用PCでは、同じPC上のブラウザーでKlacksを開く場合、セットアップコードは不要です。別のコンピューターからは、ログインページだけが表示されます。
- 代わりにログインページが表示される場合(たとえばセットアップコードなしでインストールした場合)、インストーラーの出力に同梱アカウントが記載されています。その場合も、Klacksはご自身の管理者アカウントの作成へ直接案内します。
- 2人が同時に送信した場合、管理者になるのは最初の1人だけです。2人目はログインページに移動します。

このゲートが意図的に無効になっているのは、Playgroundとローカルの開発環境だけです。そこでは同梱のアカウントが残ります。

## 知っておくと良いこと

- **前提条件:** RAM 8 GB以上と4 vCPU、Compose v2対応のDocker(Linuxでは、確認のうえインストーラーがDockerをインストールします)、空きポート80と443、そして`ghcr.io`と`github.com`へのHTTPSによる外向きアクセス。詳細と、小さいホスト向けの計算例は、[システム要件](../betrieb/systemvoraussetzungen.md)を参照してください。
- 付属のアップデートサービスが、各アップデート前のバックアップと問題発生時の自動ロールバックとともに、インストールを自動的に最新の状態に保ちます。詳しい流れは、[アップデートとロールバック](../betrieb/updates-und-rollback.md)を参照してください。
- データは、自社のインフラ上にある自社のデータベースに保存されます。ただし、一部の機能は外部サービスを呼び出します。どのサービスかは、次のセクションに記載しています。
- インストーラーを再度実行しても害はありませんが、アップデートにはなりません。パスワード、証明書、初回インストール時に決まったバージョンはそのまま保持され、スタックが再起動されます(Linuxでは、最初に`sudo`でインストールした場合、今回も`sudo`を付けます)。これは、動かなくなったスタックを修復する方法です。新しいバージョンを適用するのは、インストーラーではなくアップデートサービスです。
- 独自の証明書を使う場合は、インストール前に、インストールフォルダー内の`nginx/certs/`に`server.crt`と`server.key`を置いてください。置かない場合、インストーラーが自己署名証明書を生成します。
- データベースのバックアップは定期的にご自身で行ってください。方法は[バックアップと復元](../betrieb/backup-und-wiederherstellung.md)を参照してください。

## Klacksが呼び出す外部サービス

データは自社のサーバーにあります。それでも、一部の機能のために、Klacksは標準の運用でインターネット上の公開サービスを呼び出します。これらのサービスのアドレスは固定で組み込まれています。独自のジオコーディング、ルーティング、地図のサーバーを指定することは、現時点ではできません。

| サービス | 用途 | 送信される内容 | 標準 | 無効化 |
|---|---|---|---|---|
| OpenStreetMapのNominatim(`nominatim.openstreetmap.org`) | 住所を座標に変換: 住所の保存時、会社の所在地、ツアー計画、および住所とグループ拠点のバックグラウンドサービスで | 番地、郵便番号、市区町村、国。個人名は含まれません。グループ拠点の場合は、地名またはグループ名 | オン | `BackgroundServices__AddressGeocoding=false`と`BackgroundServices__GroupGeocoding=false`で無効になるのはバックグラウンドサービスのみです。住所の保存時には引き続きジオコーディングされます。 |
| 公開OSRMサーバー(`router.project-osrm.org`) | 移動時間、距離、地図上のルート | 訪問先の座標。名前は含まれません | OpenRouteServiceのキーが登録されていない間はオン。Klacksサーバーがルートを返さない場合は、ブラウザーも直接OSRMに問い合わせます | 用意されていません |
| OpenRouteService(`api.heigit.org`) | OSRMと同様。加えて自転車と徒歩 | 訪問先の座標。名前は含まれません | APIキーが登録されている場合のみ | 設定 > OpenRouteでキーを削除 |
| 地図タイル(OpenStreetMap、OpenStreetMap.de、またはCARTO) | ダッシュボードでの地図表示 | ブラウザーから: IPアドレスと表示している地図の範囲 | 地図が表示された時点でオン | 地図上でプロバイダーを選択可能。独自のタイルサーバーは不可 |
| GitHub(`github.com`)とGitHub Container Registry(`ghcr.io`) | インストールと自動アップデート: リリースマニフェストとDockerイメージ | 通常のダウンロードリクエスト。計画データは含まれません | オン | — |
| Klacksマーケットプレイス(`klacks-software.ch/store`) | 言語パッケージと国別パッケージ | 国コード、パッケージコード、または検索語 | パッケージ検索時と国別プロファイルの取得時 | アドレスは`LanguagePlugins__MarketplaceUrl`で設定可能 |
| Hugging Face(`huggingface.co`) | Klacksy用の検索モデルを一度だけダウンロード | 顧客データは含まれません(ファイルのダウンロード) | 最初に必要になった時点 | — |
| Open-Meteo(`api.open-meteo.com`、`air-quality-api.open-meteo.com`) | ウェルカムウィジェットの天気と大気質の表示、Klacksy経由の天気の問い合わせ | ブラウザーの座標(許可されている場合)または会社の所在地の座標 | オン | `Assistant__Ambient__Enabled=false`で無効になるのは、大気質と祝日の表示のみで、ウェルカムウィジェットの天気の問い合わせは対象外です |
| Nager.Date(`date.nager.at`) | ウェルカムウィジェットの祝日表示 | 国コード | オン | `Assistant__Ambient__Enabled=false` |
| クラウドAIプロバイダー(例: OpenAI、Anthropic、Google、DeepSeek) | Klacksと、AIを活用したバックグラウンド機能(例: グループ拠点の分類) | リクエストと、そのために必要なお客様のデータからのコンテキスト | クラウドモデルが設定されている場合のみ | ローカルモデルを使用 |
| 音声、検索、翻訳サービス(例: Deepgram、Groq、AssemblyAI、Edge TTS、OpenAI TTS、ElevenLabs、Google Cloud TTS、DeepL、Web検索) | 音声入力と音声出力、Web検索、翻訳 | 音声またはテキスト | 利用または設定した場合のみ。ブラウザーの音声認識は、ブラウザーによってはそのオンラインサービスを経由して動作します | 機能を使用しない |

「無効化」列のスイッチは、`klacks-api`コンテナーの環境変数です。`docker-compose.yml`の、このサービスの`environment:`に記述してください。`.env`ファイルにだけ記述しても、サービスが`env_file`として読み込まないため、効果はありません。

ローカルAIモデルを使うと、言語モデルへのリクエストが外部のAIプロバイダーに送られることはありません。この表のその他のサービスには、影響しません。
