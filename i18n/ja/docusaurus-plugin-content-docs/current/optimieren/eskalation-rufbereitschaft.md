# エスカレーションとオンコール

誰かが欠勤し、勤務の開始まであと数時間しかありません。そうした場合Klacksは、チーム全員を手当たり次第に呼び起こすのではなく、あらかじめ登録された呼び出しリストを順に処理します — 誰かが引き受けるまで、一人ずつです。

## 仕組み

- **連鎖のきっかけは欠勤の穴埋めです**: 欠勤した人が勤務を持っていた影響日ごとに、Klacksはその勤務にひも付いた個別のエスカレーションを作成します(参照: [欠勤を一目で把握](./absenzen-im-blick.md))。
- **呼び出しリストは一度だけ設定します**: 設定 > エスカレーション呼び出しリストには、グループ表示権限と電話番号が登録されているすべてのユーザーが並びます。順番はドラッグ&ドロップで決め、即座に保存されます — 事業所全体で共通の一つの順番です。
- **実際に誰が呼ばれるかは、その場になって決まります**: Klacksは登録した順番の中から、対象の上位グループへの表示権限を持つ人を選び、現在不在として登録されている人は全員飛ばし、最後にAdministratorをセーフティネットとして追加します。
- **通知は複数の経路で届きます**: 依頼は必ずKlacksの受信箱に届き、ログイン中の人にはアプリ内に即座に表示され、さらに接続済みのメッセンジャーを通じても届きます — 深夜3時に開いたブラウザの前に座っている人はいないからです。メッセンジャー連携と連鎖の自動的な繰り上げは、インストールごとに有効化されます。
- **引き受けの返事はひと言で済みます**: 現在依頼を受けている人は、メッセンジャーで短く返信します(「引き受けます」)。Administratorは代わりに*進行中のエスカレーション*ページの*引き受ける*を使うこともできます。その後、引き受けた人には確認が届き、それ以前に依頼されていた人全員には静かな通知が届きます — 誰も二度は起こされません。

## 知っておくと良いこと

- 期限は勤務開始そのものではなく、その手前に設定されたリードタイムです(標準では2時間)— こうすることで、引き受けた人にも出発の準備をする時間が残ります。
- 各ステップに与えられる時間は、Klacksが残りの期限から算出します: 勤務開始が近づくほど、1回あたりの時間は短くなります。順番に依頼していく余裕がなくなった場合、Klacksは残り全員に同時に依頼します。
- *進行中のエスカレーション*ページでは、各ステップの状況を確認できます — 待機中、依頼済み、引き受け済み、応答なし、スキップ、キャンセル済みです。エスカレーションが進行中の場合、ヘッダーにも警告アイコンが追加で表示されます。
- 呼び出しリストと概要画面はAdministrator専用です(参照: [ロールと権限](../erste-schritte/rollen-und-rechte.md))。Administratorは進行中のエスカレーションを中止できます — その際は理由の入力が必要で、後から連鎖が止められた理由をたどれるようにします。
- ユーザーアカウントに電話番号が登録されていない人は、そもそも呼び出しリストに表示されません。メッセンジャー経由の依頼には、さらに連携済みのメッセンジャー連絡先が必要です。オンコール担当者の不在は同じリストで直接管理します: 開始日〜終了日、理由は任意入力、必要に応じて無期限にも設定できます。
