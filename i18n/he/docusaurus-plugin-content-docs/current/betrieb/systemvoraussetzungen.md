# דרישות מערכת וארכיטקטורה

Klacks רצה כסטאק Docker על השרת שלכם. עמוד זה מתאר אילו שירותים עולים בכך וכיצד לקבוע את גודל המארח — כולל המדידות שעליהן מבוססת ההמלצה.

## המבנה: חמישה שירותים

חבילת ה-On-Premise מפעילה אך ורק את מה שנדרש לתפעול:

| שירות | תמונה (Image) | תפקיד |
|---|---|---|
| `klacks-postgres` | `pgvector/pgvector:pg17` | מסד נתונים; הרחבת הווקטורים כלולה כבר |
| `klacks-api` | `ghcr.io/heribertg/klacks-api` | Backend; מבצע מיגרציה ומאכלס את מסד הנתונים בעת ההפעלה |
| `klacks-ui` | `ghcr.io/heribertg/klacks-ui` | ממשק Angular, מוגש באמצעות nginx |
| `klacks-updater` | `ghcr.io/heribertg/klacks-updater` | מחיל עדכונים חתומים (api ו-ui יחד) |
| `klacks-proxy` | `nginx:alpine` | סיום TLS ו-Reverse Proxy |

שירותים פנימיים של היצרן (מאגר ידע לפיתוח, שיווק, שוק, pgAdmin, certbot, ממשק Blazor) **אינם** כלולים במכוון. כמפעילים אתם רואים אפוא רק את הסטאק שלכם.

## מה המארח צריך להביא

- **8 GB RAM ו-4 vCPU** כמינימום (ראו החישוב להלן).
- Docker Desktop ‏(Windows/macOS) או Docker Engine עם Compose v2 ‏(Linux), **‏amd64 או arm64**.
- פורטים פנויים **80 ו-443** — ניתנים לדריסה באמצעות `HTTP_PORT` ו-`HTTPS_PORT`.
- גישת HTTPS **יוצאת** אל `ghcr.io` ‏(תמונות) ואל `github.com` ‏(מניפסט העדכון החתום).
- אופציונלי: גישה אל `klacks-software.ch:7553` עבור חבילות מדינה ותוספי שפה מהשוק.

## זיכרון: למה 8 GB, ומה קורה במארחים קטנים יותר

Klacks מפעילה את שני מודלי החיפוש שלה (Embedder ו-Reranker) **מקומית בתוך** התהליך `klacks-api`. שני סשני ה-ONNX נשארים בזיכרון באופן קבוע — הם אינם נפרקים לאחר כל שאלה.

נמדד על מארח הייצור של היצרן ב-12.09.2026:

- עומס הבסיס של התהליך: כ-1,017 MB
- Embedder: כ-1,171 MB
- Reranker: כ-116 MB
- סך הכול: מישור יציב של כ-**2,304 MB**
- תחת מגבלה של 2,560 MB הליבה (Kernel) סיימה את הקונטיינר ב-2,471 MB (OOM).

לכן ה-Compose המצורף קובע **3,584M** ו-3.0 CPU עבור `klacks-api`, כשפריקה בזמן סרק מכובה. על פני הסטאק כולו: 3,584M ‏(api) + 2,048M ‏(postgres) + 3 × 256M ‏(ui, updater, proxy) = **6,400 MiB**, והיתרה מתוך 8 GB נשארת למערכת ההפעלה ולמטמון הקבצים.

**מארח קטן יותר, כ-3 GB עבור `klacks-api`:** קבעו בקובץ `.env` את **שתי** השורות הבאות — לעולם לא את שורת הזיכרון לבדה:

```bash
KLACKS_API_MEMORY_LIMIT=2560M
KLACKS_API_IDLE_UNLOAD_MINUTES=30
```

הפריקה בזמן סרק משחררת סשן לאחר 30 דקות ללא גישה. המחיר: השאלה הבאה לאחר מכן טוענת אותו מחדש (כ-2.2–2.9 שניות עבור ה-Embedder, כ-1.1 שניות עבור ה-Reranker). ערכים בין 1 ל-5 מועלים ל-5, ו-`0` פירושו: לעולם לא לפרוק.

## CPU: פחות ליבות רק מאטות, הן לא שוברות

החיפוש עובד גם עם פחות ליבות, אך נעשה איטי יותר — ה-Reranker הוא השלב הכבד חישובית. נמדד: 2,994–3,163 מילישניות עבור 25 מועמדים עם 3.0 CPU לעומת 4,339–4,860 מילישניות עם 1.5 CPU, שבהם השירות בילה בנוסף 7.15 שניות תחת Throttling. עבור מארח קטן יותר:

```bash
KLACKS_API_CPU_LIMIT=1.5
```

מכסות ה-CPU של הסטאק מסתכמות במכוון ל-4.75 על 4 vCPU: מכסה היא תקרה, לא הקצאה, והשירותים לעולם אינם מגיעים לשיא בו-זמנית.

## טוב לדעת

- **סיסמאות ומפתחות נשארים יציבים.** ‏`POSTGRES_PASSWORD` צרוב ב-volume הנתונים בהפעלה הראשונה — שינוי מאוחר יותר הופך את מסד הנתונים ליתום. ‏`JWT_SECRET` חותם את הסשנים; שינוי שלו מנתק את כל המשתמשים. המתקין שומר על שניהם בכל הרצה חוזרת.
- **`COMPOSE_PROJECT_NAME=klacks`** קבוע בקוד, כדי שהמארח ושירות העדכונים יצביעו על אותו פרויקט Compose ללא תלות בשם התיקייה. אין לשנות אותו לאחר ההתקנה.
- **`KnowledgeIndex__WarmupEnabled=false` אינו אפשרות לחיסכון בזיכרון.** הוא רק מזיז את בניית החיפוש מההפעלה לבקשת הצ'אט הראשונה; בפעילות שוטפת הסשנים נוכחים באותה מידה. שימושי רק אם המארח נכשל בהפעלה בגלל זיכרון.
- **יותר ממופע API אחד?** אז נדרש SignalR Backplane. Klacks אינה מספקת כזה: הקימו בעצמכם שירות תואם RESP (למשל Valkey — מורשה מאז 7.4 תחת BSD-3, בניגוד ל-Redis) והפעילו את ה-Upstream הדביק (`ip_hash`) המוכן בתבנית ה-nginx. ללא Backplane רץ בדיוק מופע `klacks-api` אחד, כמו בכל התקנה כיום.
- **פרופילי מדינה:** המתקין מכיר 30 פרופילים: `ae`, `at`, `ch`, `cn`, `cz`, `de`, `dk`, `es`, `fi`, `fr`, `gb`, `gr`, `id`, `il`, `it`, `jp`, `kr`, `li`, `my`, `nl`, `no`, `pl`, `pt`, `ro`, `sa`, `se`, `th`, `tw`, `us`, `vn`. פרופיל קובע בהפעלה הראשונה שפה, מדינה/אזור ואזור זמן, לוח חגים, סוף שבוע ותחילת שבוע, גבולות שעות עבודה, זכאות לחופשה, תוספות, את מערכת היעד הרגילה לייצוא שכר (לשווייץ למשל `abaconnect-ch`) וכן תבניות ענפיות — עבור ספיטקס (Spitex) למשל תבנית כללי התכנון "CH Spitex Standard". ללא פרופיל Klacks מתחילה ניטרלית ואתם מגדירים הכול ידנית.
