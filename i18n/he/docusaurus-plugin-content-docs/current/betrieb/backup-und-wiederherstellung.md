# גיבוי ושחזור

הנתונים שלכם נמצאים כולם על התשתית שלכם — ולכן גם הגיבוי באחריותכם. עמוד זה מראה מה צריך לגבות וכיצד משחזרים.

## מה צריך לגבות

| מה | היכן | באיזו תדירות |
|---|---|---|
| מסד נתונים | ה-volume ‏`postgres_data` | מדי יום, לכל הפחות לפני כל עדכון |
| קבצים שהועלו | ה-volume ‏`api-uploads` | יחד עם מסד הנתונים |
| מסמכים | ה-volume ‏`api-documents` | יחד עם מסד הנתונים |
| צרור מפתחות | ה-volume ‏`api-dataprotection` | יחד עם מסד הנתונים, **בהחלט** |

ה-volume ‏`api-dataprotection` מכיל את צרור המפתחות ש-Klacks משתמשת בו כדי לפענח הגדרות מוצפנות (למשל פרטי גישה לערוצי תקשורת). מסד נתונים ללא צרור המפתחות הזה אמנם קיים, אך אינו שמיש במלואו — גבו אותו תמיד.

## גיבוי מסד הנתונים

```bash
docker exec klacks-postgres pg_dump -U admin -d Klacks -Fc > klacks-20260922.dump
```

הפורמט `-Fc` (custom) דוחס ומאפשר בעת השחזור לבחור טבלאות בודדות.

## שחזור מסד הנתונים

```bash
docker exec -i klacks-postgres pg_restore -U admin -d Klacks --clean --if-exists < klacks-20260922.dump
```

`--clean --if-exists` מסיר מראש אובייקטים קיימים, כדי שהשחזור לא ייכשל בגלל טבלאות שכבר קיימות.

## מכשול: חזרה לאחור לאחר מיגרציה שנכשלה

בדיוק כאן נוצרה בעבר השבתת ייצור, והמנגנון הוא של כל חזרה לאחור המבוססת על Dump:

אם גרסה פגומה יוצרת באמצעות מיגרציה **טבלאות חדשות**, טבלאות אלה אינן ב-Dump. לכן בעת השחזור מסד הנתונים אינו נשאר במצב הישן — הטבלאות החדשות **שורדות** את השחזור, בעוד היסטוריית המיגרציות (`__EFMigrationsHistory`) מאופסת למצב הישן. ניסיון ההפעלה הבא נתקל בשגיאה `42P07: relation "…" already exists` וההתקנה נתקעת בלולאת הפעלה מחדש.

אם אתם חוזרים לאחור ידנית לאחר עדכון שנכשל, בדקו לכן לאחר השחזור אם נותרו טבלאות שלא היו קיימות בגרסה הישנה, והסירו אותן **לפני** שאתם מפעילים שוב את ה-API.

## שמירה ומחיקה

Klacks אינה מוחקת נתונים רק באמצעות סימון מחיקה, אלא **פיזית**. שירות רקע רץ מדי יום ומסיר באופן בלתי הפיך את כל השורות המסומנות כמחוקות שזמן המחיקה שלהן מוקדם מהתקופה שהוגדרה — וזאת בכל הטבלאות עם סימון מחיקה (עובדים, כתובות, קבוצות, משמרות, שעות עבודה, היעדרויות, הפסקות וכן הלאה). אין רשימת חריגים; חובת המחיקה קודמת במכוון ליכולת השחזור.

את התקופה שולטים באמצעות ההגדרה `DATA_RETENTION_DAYS`; ללא ציון משלכם חל ערך ברירת המחדל **3,650 ימים (10 שנים)**. העמוד [שמירת נתונים](../../einstellungen/system-sicherheit/datenaufbewahrung/) מתאר את ההגדרה בפירוט.

## טוב לדעת

- **לפני כל עדכון Klacks מגבה בעצמה.** שירות העדכונים יוצר גיבוי נתונים לפני שהוא מפעיל גרסה חדשה; בעת מיגרציה הגיבוי נקשר לפעולת העדכון ומשמש שוב לחזרה לאחור אוטומטית או ידנית. זה אינו מחליף גיבוי **חיצוני** משלכם — הוא מגן בדיוק במקרים שבהם המארח עצמו נפגע.
- **בדקו את הגיבוי שלכם.** Dump שמעולם לא שוחזר הוא הנחה, לא גיבוי. צרו מסד נתונים זמני ושחזרו לתוכו לפני שאתם סומכים על התהליך.
- **שמרו את צרור המפתחות בנפרד ממסד הנתונים.** אם `api-dataprotection` נמצא באותה קבוצת גיבוי ואותו אירוע פוגע בשניהם, ההצפנה חסרת ערך.
