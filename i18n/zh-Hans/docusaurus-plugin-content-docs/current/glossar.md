# 术语表

Klacks 及本文档中反复出现的术语 — 简明扼要，并按您遇到它们的先后顺序排列。

## 排班

**员工行**
最小的可排班单位。它既不是某个人，也不是某一天，而是某个人在具体某份排班表中的那一行。所有排班数值都挂在这一行上。

**排班表**
一个收集员工行**引用**的容器 — 而不是副本。因此，一个人无论出现在多少份子排班表中，都只存在一次，任何改动会立即在各处可见。它是[模块化排班](../planen/modulare-planung/)的基础。

**自动排班**
助手按照您的规则填充排班。计算在后台运行，您可以继续工作 — 参见[自动排班](../planen/auto-planung/)。

**可用性**
一个人何时可以投入工作 — 精确到小时或天，对自有员工和外部员工均适用。参见[可用性网格](../planen/verfuegbarkeits-raster/)。

**订单（委托）**
一次工作安排的草稿，仍可编辑。订单**尚不可排班**。

**封存**
只能执行一次、**不可撤销**的步骤，它把订单变成可排班的班次。此时会同时生成与订单对应的可排班部分。Klacks 中无法直接创建可排班班次 — 每个班次都是通过封存产生的。参见[班次的生命周期](../planen/schicht-lebenszyklus/)。

**班次（排班）**
可排班的、已封存的工作安排。「排班」一词指的是同一个东西。

**审批级别（班次计划）**
班次计划按固定顺序经历四种状态：**草稿 → 已确认 → 已批准 → 已完成**。任何已登录的账号都可以确认；批准只有 Supervisor 和 Admin 可以进行；结束则仅限 Admin。参见[审批流程](../planen/freigabe-workflow/)。

**期间 / 期间结算**
结算周期（每周、每两周、每月或自定义；通过支付周期设定）。结算使一个期间具有约束力，且仅限 Admin 操作 — 参见[期间结算](../planen/periodenabschluss/)。

**缺勤 — 两件事，一个词**
在基础数据领域，「缺勤」指**缺勤类型目录**（名称、颜色、默认时长、默认值）。而日历中的条形块则要么是**意愿**（计划中的缺勤，可自由拖动，没有锁定级别），要么是**已登记的缺勤**（从排班计划中带入，在缺勤页面中只读，带有锁定级别）。把两者混淆，就会找错地方。

## AI 助手

**Klacksy**
Klacks 的 AI 助手。它负责排班、解释和执行 — 模型可自由选择。参见 [Klacksy](../ki/klacksy-ki-assistent/)。

**技能**
Klacksy 一项单独的、边界清晰的能力 — 是对具体程序逻辑的声明式封装（「搜索员工」「分配合同」「生成报表」）。Klacksy 会在运行时选择合适的技能。

**自主等级**
Klacksy 在不征求意见的情况下可以走多远：

| 等级 | 名称 | 行为 |
|---|---|---|
| 0 | 仅建议 | 每个写入操作都需要您确认 |
| 1 | 辅助 | 可撤销的操作自由执行；不可撤销和敏感的操作会先询问 |
| 2 | 自主（默认） | 除被归为敏感的操作外，其余全部自由执行 |
| 3 | 完全自主 | 连不可撤销的步骤也会直接执行 |

敏感操作 — 例如删除用户或更改权限 — 在**任何**等级下都会询问。参见[自主等级](../einstellungen/klacksy-konfiguration/autonomie-stufen/)。

## 角色与运营

**Admin / Supervisor / 计划员**
三种访问级别。Admin 可以做一切，Supervisor 可以创建和编辑，没有角色的账号是计划员。概览见[角色与权限](../erste-schritte/rollen-und-rechte/)。

**国家配置文件**
为某个国家预先准备好的一套设置：语言、时区、节假日日历、周末与每周起始日、工时上限、休假额度、附加津贴、默认工资导出，以及行业模板。安装时通过 `REGION` 选择。

**Playground**
带有演示数据的公开测试实例，位于 [play.klacks-software.ch](https://play.klacks-software.ch) — 明确用于试用，不含真实的个人数据。参见[安装与 Playground](../erste-schritte/installation-und-playground/)。

**本地部署（On-Premise）**
在您自己的基础设施上运行：您的硬件、您的数据库、您的数据。与托管方式相对。

**更新服务**
随套件提供的服务，负责应用签名更新 — 事先备份，出现问题时自动回滚。参见[更新与回滚](../betrieb/updates-und-rollback/)。

**角色与数据保护**
Klacks 不会向外「报告」：不会有任何数据回传给厂商。对于确实需要删除的数据，由[数据保留](../einstellungen/system-sicherheit/datenaufbewahrung/)负责 — 删除的内容在期限届满后会被物理清除。
