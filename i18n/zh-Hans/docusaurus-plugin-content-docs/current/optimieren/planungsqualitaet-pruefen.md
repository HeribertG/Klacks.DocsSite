# 检查排班质量：违规、缺口与被跳过项

排班助手运行结束后，Klacks 会在结果旁边放上三张诊断表：排班在哪里触及了某条规则、哪里缺少某项资质，以及哪些内容根本没有被排入。

## 运作方式

这三份报告出现在相应排班助手的对话框中 — 而不是在排班网格里。它们是助手运行结果的一部分，只有管理员可见，因为自动排班整体上需要管理员角色。每份报告都会在标题中注明条目数量，并且**如果没有发现任何问题，则根本不会显示** — 因此，看不到某个卡片正是好消息。

**如何进入这些对话框：** 排班表中的魔杖按钮在默认状态下会直接启动一次排班运行，不显示任何对话框。管理员可用 **Ctrl+Shift+H** 将该按钮切换为下拉菜单，列出各个排班助手（Plan、Fuzzy Harmonizer、Holistic Harmonizer、Background Optimizer、Recovery）— 只有通过这个下拉菜单，才会打开带诊断表的对话框。

**资质缺口** 与结果一同出现，也就是在您*采纳*结果*之前*。列：严重程度、班次、日期、所需资质、原因 — 一旦至少有一行涉及具体人员，还会额外出现「员工」列。原因栏会显示*不具备*、*已过期*或*等级不足*。背后是两种不同情形：要么某个班次名额空缺，是因为没有任何具备所需资质的可用人选 — 此时该行不会提及具体人员；要么某人留在了一个他/她并不具备资质的班次上 — 此时会显示其姓名。如果资质只是在系统中缺失，请为该人员补录；[资质目录](../einstellungen/stammdaten-organisation/qualifikationen.md) 介绍了资质的维护方法。否则，请改排他人，或调整该班次的资质要求。

**合规违规项** 出现在您*采纳*结果*之后*。列：日期、员工、备注；备注以明文说明所违反的规则及具体数值。红色行表示错误，黄色表示警告与提示。对于两个协调助手而言，报告只显示新场景相对于实际排班表**新增**的内容 — 以及其中有多少违规项属于阻断模式。这些违规项会阻止该场景被采纳，直到问题被解决，或由有权限的人员明确覆盖为止。

**被跳过的分配** 仅在排班助手中出现，同样是在采纳之后 — 并且始终显示为红色。列：日期、员工、班次、原因。这里记录的不是排定了什么，而是 Klacks 有意**没有**写入的内容：那些会违反阻断模式规则的分配。原因以简短分类形式呈现（「休息时间过短」「连续工作日过多」「时间冲突」……）。视具体情况，Klacks 会向有权限的人员提供以覆写方式仍然采纳该次运行的选项；其他人则会收到提示，建议启用覆写后重新运行助手，或请有权限的人员协助。每一次覆写都会被记录在案。

哪些规则会被检查、检查的严格程度如何，由您在 [排班规则](../planen/planungsregeln.md) 中设定；排班本身是如何生成的，则由 [自动排班：数秒生成排班表](../planen/auto-planung.md) 介绍。

## 小贴士

- 一个被阻断的条目不会导致整份排班表被放弃：只有受影响的分配会被移除，同一人的其他正常条目仍会照常写入。
- 资质缺口的严重程度遵循一条简单规则：只有当一项被标记为强制的资质完全缺失时，才算**错误**。资质过期、等级不足以及任何可选要求，都只显示为**警告**。
- 只有在真的没有任何可用人选具备所需资质时，空缺的班次名额才会出现在资质缺口中。如果是出于其他原因而空缺，则属于普通的覆盖不足，不会在此报告。
- 如果自动排班以整体运行的方式执行，Klacks 只会以一条简短提示的形式汇报结果，并注明资质缺口的数量 — 详细的表格属于各个助手自己的对话框。
- 这些报告纯粹是只读视图：无法编辑，也不会改动任何内容。修正需要在 [排班网格：您的交互式时间矩阵](../planen/plan-raster.md) 中进行，或者重新运行一次。
