# 升级与待命

有人临时缺勤，而班次几小时后就要开始。此时 Klacks 不会毫无章法地唤醒整个团队，而是按照预先设置好的呼叫名单逐一联系 — 一个接一个，直到有人接手。

## 运作方式

- **触发条件是填补一次缺勤缺口**：对于缺勤人员原本有班次的每一个受影响的日子，Klacks 都会建立一条独立的升级流程 — 并关联到这个具体的班次（参见[缺勤一目了然](./absenzen-im-blick.md)）。
- **呼叫名单只需设置一次**：在「设置 > 升级呼叫名单」中，列出了所有具备分组可见性且已登记电话号码的用户。顺序由您通过拖放方式确定，并会立即保存 — 这是适用于整个机构的统一顺序。
- **真正被联系的人选，在实际发生时才确定**：Klacks 会从您设定的顺序中，挑出对上级分组具有可见性的人员，跳过所有当前被登记为缺席的人，并将管理员作为兜底选项附加在末尾。
- **通过多种渠道发出通知**：请求始终会进入 Klacks 收件箱，已登录人员会立即在应用内看到提示，此外还会通过接入的消息渠道发出 — 因为凌晨三点不会有人守在打开的浏览器前。消息渠道对接与升级链的自动推进，均按安装实例逐一开通。
- **一个词即可接受任务**：正在被请求的人只需在消息渠道中简短回复（「我来处理」）；管理员也可以改在「进行中的升级」页面上使用「接手」。之后，接受任务的人会收到一条确认，之前所有被请求过的人则会收到一条静默提示 — 不会有人被二次唤醒。

## 小贴士

- 期限指的不是班次开始时刻本身，而是它之前的一段提前量（默认 2 小时）— 这样接手的人还有时间赶赴现场。
- 每一级有多少时间，由 Klacks 根据剩余期限计算：班次越临近，每一轮的时间就越短。如果时间紧张到无法逐一进行，Klacks 会同时向所有剩余人员发出请求。
- 在「进行中的升级」页面上，您可以看到每一级的状态 — 等待中、已请求、已接手、无响应、已跳过或已取消。有升级正在进行时，页头还会额外显示一个警示图标。
- 呼叫名单与总览仅限管理员使用（参见[角色与权限](../erste-schritte/rollen-und-rechte.md)）。管理员可以中止正在进行的升级 — 但须说明理由，以便日后能够追溯升级链被停止的原因。
- 用户账户中未登记电话号码的人，根本不会出现在呼叫名单中。要通过消息渠道发出请求，还需要额外绑定一个消息渠道联系方式。待命人员的缺勤直接在同一份名单中维护：起止日期，可选填写原因，也可以设为长期有效。
