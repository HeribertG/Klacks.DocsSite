# 薪资导出交接

在封存一个按分组划分的期间时，Klacks 可以将其薪资数据自动交接给外部薪资系统。本页说明这需要哪些前提条件，以及为什么这次交接有时看似什么都没有送达 — 这是围绕此功能最常见的支持案例。

## 运作方式

**前提条件：薪资导出扩展包。** 自动交接给薪资系统并非核心功能，而是需要一个独立的扩展包，该扩展包必须在「设置 > 功能插件」中已安装**并且**处于启用状态。如果缺少该扩展包，或者它只是被禁用，交接就完全不会产生任何结果 — 没有文件，没有提示，也没有您能看到的任何条目。这比导出设置中被禁用的某个导出格式还要严格：那种情况至少会在服务器日志中留下一条记录；而这里连日志都没有。

**一次性交接（幂等性）。** 自动交接对于「分组 + 目标系统 + 精确日期范围」这一组合，只会恰好运行一次 — 这可以防止相同的薪资数据被意外重复送达薪资系统。如果您重新打开一个已封存的期间，做出修正后再次封存，第二次交接会被悄悄跳过：因为对于这个精确组合，已经存在一条交接记录，重新打开也不会移除它。

**手动下载同样计数。** 针对同一分组/同一目标系统/同一时间段的一次按需手动薪资下载，会生成与自动交接完全相同的记录。如果手动下载在自动交接之前执行，就会为受影响的时间段「占用」自动交接的名额，效果与该交接已经自动运行过一样。

| 为什么没有收到（新的）数据？ | 是否存在记录？ | 是否会阻塞之后的手动下载？ |
|---|---|---|
| 扩展包未安装/未启用 | 否 | 否 |
| 针对这个精确组合已经交接过 | 是（在期间结算的「日志」标签页中可见） | 否 |

**两个需要注意的细节：**

- 手动下载**不会**套用支持团队可能为该目标系统配置的导出格式修正 — 即使该目标系统存在一条在自动流程中会生效的有效修正，手动下载也始终使用标准值。
- 一次性锁定是精确匹配的：只有分组、目标系统和起止日期完全相同时才会生效。不同的时间段或不同的目标系统，不会因为之前的一次交接而被阻塞。

**如果封存后没有任何数据送达，或者需要补送修正后的数字：** 请先检查对应的扩展包是否已在「设置 > 功能插件」中安装并启用。在重新打开并修正之后，将修正后的数字送达薪资系统的可靠方式是使用期间结算区域中的**手动导出**（「导出」标签页）— 它既不受扩展包锁定的限制，也不受自动交接的一次性锁定的限制。由于它同样不会套用导出格式修正，在这种情况下，请手动核对导出的数字与可能生效的修正是否一致。

## 小贴士

- 每一次交接的前提，都是一个已封存、按分组划分的期间 — 期间如何封存，请参见 [期间结算](../../planen/periodenabschluss.md) 页面。封存与重新打开在该页面上仅限管理角色使用。
- 本页描述的是薪资数据从 Klacks 到薪资系统的**导出**。反方向的流程 — 订单从 ERP 系统**导入**到 Klacks — 请参见 [ERP 接入点](./erp-uebernahmepunkte.md)。
- 扩展包在「设置 > 功能插件」中统一管理：安装、启用/禁用或彻底移除。
- 一个被禁用的扩展包仍处于已安装状态，但会像未安装一样，完全锁定自动交接功能。
