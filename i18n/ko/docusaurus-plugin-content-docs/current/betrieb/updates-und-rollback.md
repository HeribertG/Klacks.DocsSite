# 업데이트와 롤백

Klacks는 스스로 업데이트됩니다 — 서명된 패키지를 사용하고, 각 단계 전에 백업하며, 문제가 생기면 자동으로 되돌립니다. 이 페이지는 그 과정에서 무슨 일이 일어나는지, 그리고 어떻게 개입할 수 있는지를 설명합니다.

## 업데이트가 진행되는 방식

1. **감지.** API는 제조사가 릴리스마다 게시하는 서명된 매니페스트를 조회합니다. 더 새로운 버전이 기록되어 있으면 업데이트가 사용 가능한 것으로 간주됩니다.
2. **백업.** 업데이트 서비스가 데이터베이스 백업을 만듭니다. 새 버전에 마이그레이션이 포함되어 있으면 이 백업은 업데이트 작업에 고정적으로 연결되어, 나중에 롤백을 위해 준비된 상태로 유지됩니다.
3. **받기와 동시 활성화.** 서비스는 `klacks-api` **및** `klacks-ui`의 새 이미지를 받아 둘을 함께 전환합니다 — 두 부분은 항상 보조를 맞춰 실행되며 서로 다른 버전으로 실행되는 일은 없습니다.
4. **점검.** 전환 후 서비스는 상세 상태 점검 `/internal/health/deep`을 호출합니다.
5. **평가.** 새 버전이 정상이면 업데이트는 성공으로 간주됩니다. 그렇지 않으면 서비스가 **두** 부분을 자동으로 이전 버전으로 롤백하고 다시 점검합니다. 이마저도 실패하면 눈에 띄도록 실패 상태로 기록됩니다.

## "서명됨"의 의미

제조사는 모든 릴리스에 서명하고, 사용자의 Klacks는 패키지를 받아들이기 전에 서명을 검증합니다. 공개 키와 매니페스트 주소는 `.env`에 들어 있는 제조사 고정값입니다:

- `UPDATE_MANIFEST_BASE_URL` — 제조사의 릴리스 소스에 고정
- `UPDATE_SIGNATURE_PUBLIC_KEY` — 제조사가 서명에 사용하는 개인 키와 일치해야 함

이 두 값은 **변경을 전제로 하지 않습니다**. 바꾸면 검증이 해제되어, 서명이 막아 주는 바로 그 허점이 열립니다.

매니페스트에는 특히 다음 항목이 들어 있습니다: 채널(`Stable` 또는 `Beta`), 최신 버전, 직접 업데이트가 가능한 최소 버전(`MinUpgradableFrom`), 게시 날짜, 데이터베이스 마이그레이션 포함 여부, 아티팩트, 서명, 변경 목록에 대한 링크.

`klacks-api`와 `klacks-ui`는 눈치채지 못하는 사이에 서로 어긋나지 않도록 `.env`에서 **정확한 버전으로 고정**되어 있습니다. 업데이트 서비스 자체는 항상 `latest`로 실행됩니다 — 의도적으로 서명된 매니페스트에 포함되어 있지 않으며, api와 ui만 교체합니다.

## 운영 중 설정

관리자 영역의 **시스템 → 업데이트**에서:

| 설정 | 효과 |
|---|---|
| **자동 업데이트 활성화** | 업데이트를 감지하고 자동으로 적용합니다 |
| **알림만 받기** | 업데이트를 **감지**만 하며, 사용자가 직접 실행할 때까지 적용하지 않습니다 |
| **유지보수 시간대** | 자동 업데이트가 실행될 수 있는 시간 범위 |

이 설정들은 데이터베이스에 저장되며, 첫 시작 때만 적용되는 `.env`의 초기값(`UPDATE_AUTO_ENABLED`, `UPDATE_NOTIFY_ONLY`)보다 우선합니다.

## 수동으로 롤백하기

자동 롤백의 경우 아무도 개입할 필요가 없습니다 — 실패한 업데이트는 서비스가 스스로 되돌립니다. 의도적으로 한 단계 이전으로 돌아가고 싶다면:

1. `.env`의 `KLACKS_API_TAG`와 `KLACKS_UI_TAG`를 이전 버전으로 설정합니다.
2. 스택을 다시 활성화합니다: `docker compose up -d klacks-api klacks-ui`.
3. **결함이 있는 버전이 이미 마이그레이션을 수행했다면**, 업데이트 전의 해당 백업도 함께 복원하십시오 — 이때 [백업 및 복원](../backup-und-wiederherstellung/) 페이지의 함정에 유의하십시오: 새 버전이 만든 테이블은 복원 후에도 남아 다음 시작을 막습니다.

## 알아두면 좋은 점

- **롤백은 비상 수단이 아니라 정상적인 경로입니다.** 모든 업데이트 작업에는 상태가 있습니다: 성공, 롤백됨, 또는 롤백 실패. 롤백된 업데이트는 기록되는 정상적인 작업이며 — 사고가 아닙니다.
- **롤백된 업데이트는 초기화된 업데이트가 아닙니다.** 롤백은 버전을 되돌릴 뿐 사용자의 데이터를 되돌리지 않습니다. 업데이트와 롤백 사이에 사용자가 변경한 데이터는 백업 시점의 상태에서 가져옵니다.
- **로그에서 확인할 수 있습니다:** `docker compose logs klacks-updater`는 감지, 백업, 전환, 롤백을 보여 줍니다.
